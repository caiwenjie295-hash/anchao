# 《暗潮》第一幕开发文档 02：网页框架开发文档

> 项目定位：约 40 分钟线性悬疑解谜网页游戏。  
> 第一幕核心：玩家以真实接管一台 Windows 11 电脑的方式，重新注意到小A，并一步步调查到鸡头岭。

## 1. 第一幕开发目标
构建一个高写实、强沉浸、可维护的网页桌面环境。

第一幕重点不是“做一个电脑皮肤”，而是让玩家真的感觉自己正在使用一台被长期使用过的私人电脑。

核心要求：
- Windows 11 风格桌面
- 微信、邮箱、浏览器等应用高度拟真
- 窗口支持拖动、缩放、最小化、最大化、遮挡、任务栏切换
- 允许部分内容进入独立 HTML 页面
- 桌面和应用内存在大量无关但合理的生活噪音
- 核心剧情内容隐藏在真实内容中
- 所有剧情数据与 UI 逻辑分离

## 2. 总体架构

### 2.1 架构原则
采用：

**桌面壳层 + 多模块应用 + 独立场景页**

桌面阶段尽量在同一套 UI 框架中完成。  
需要强转场或强氛围时，可切换到独立 HTML 页面。

所有剧情内容必须数据化，不直接写死在 UI 组件中。

## 4. 第一幕页面层级

### 4.1 一层：桌面壳层
负责：
- 桌面背景
- 任务栏
- 应用图标
- 窗口拖动
- 窗口缩放
- 最小化 / 最大化 / 关闭
- 窗口层级
- 系统时间
- 系统托盘
- 系统通知
- 应用间切换

### 4.2 二层：应用模块
包括：
- 微信
- 邮箱
- 浏览器
- 资源管理器
- 记事本
- 照片查看器

这些应用必须具备真实内容层，而不是只保留剧情按钮。

### 4.3 三层：独立场景页
用于：
- 鸡头岭山路
- 山洞
- 破庙
- 特殊照片处理场景（如不放在桌面应用内）

## 5. 应用模块职责

### 5.1 微信模块
负责：
- 联系人列表
- 历史聊天
- 实时消息触发
- 母亲主动发消息
- 小月历史聊天
- 生活剧情承载
- 图片消息
- 文件消息
- 未读红点
- 聊天图片查看

要求：
- 联系人不能只有剧情角色
- 必须存在大量生活对话
- 核心剧情应藏在正常聊天中
- 母亲消息作为第一幕重要触发点

### 5.2 邮箱模块
负责：
- 邮件列表
- 搜索
- 文件夹切换
- 已读 / 未读状态
- 关键邮件
- 大量噪音邮件

邮箱内容需要包含：
- 新闻订阅
- 招聘推送
- offer
- 面试邀请
- 拒信
- 验证码
- 广告
- 学校通知
- 购物通知
- 小A关键邮件

关键要求：  
小A邮件不能成为一打开邮箱就唯一显眼的内容。

### 5.3 浏览器模块
负责：
- 搜索栏输入
- 搜索建议
- 搜索结果页
- 标签页
- 历史记录
- 页面跳转
- 新闻
- 百科
- 论坛
- 地图
- 徒步攻略
- 地方网站

搜索必须具备真实噪音：
- 强相关结果
- 弱相关结果
- 无关结果
- 同名地点
- 旧闻
- 营销页
- 百科
- 自媒体
- 论坛
- 广告

原则：  
玩家是在筛选信息，不是在点击唯一正确答案。

### 5.4 记事本模块
负责：
- 自动记录关键线索
- 玩家自由输入
- 当前待确认问题
- 弱提示
- 防卡辅助

不建议：
> 下一步请搜索鸡头岭

建议：
> 七公里的路线，为什么连人或尸体都找不到？

### 5.5 资源管理器模块
负责：
- 本地文件浏览
- 生活文件
- 照片存储
- 下载文件
- 调查中获得的截图
- 后续照片编辑入口

生活文件必须包含无剧情内容。

### 5.6 照片查看器模块
负责：
- 图片查看
- 放大缩小
- 简单编辑
- 曝光 / 阴影 / 对比度调整
- 第一幕关键谜题：发现双S

## 6. 窗口系统要求
必须实现：
- 拖动窗口
- 调整尺寸
- 最小化
- 最大化
- 还原
- 关闭
- 窗口遮挡
- z-index 层级
- 点击任务栏恢复
- 双击标题栏最大化
- 当前活动窗口高亮
- 窗口位置记忆

建议：
- 支持多个应用同时打开
- 保留用户上一次窗口位置
- 重新进入游戏后恢复桌面状态

## 7. 第一幕真实感要求

### 必须做到
- 不要所有应用都只包含剧情内容
- 不要所有联系人都只服务主线
- 不要所有邮件都能推进剧情
- 不要所有搜索结果都可疑
- 不要所有可点击物都包含线索

### 核心原则
**玩家必须感觉自己是在真实环境中自己找到线索，而不是游戏把线索一项项递给他。**

## 8. 搜索系统规则
搜索页面必须构建成一个“小型伪互联网”。

例如搜索 `鸡头岭`，结果可包括：
- 鸡头岭徒步攻略
- XX县鸡头岭天气
- 鸡头岭村历史
- 农家乐
- 摄影采风
- 同名地点百科
- 其他年份事故
- 真正的失踪新闻

玩家可以点开部分无关页面。  
即使页面无剧情价值，也要尽量做成完整、可信的简版页面。

## 9. 状态与数据要求
所有剧情推进必须依赖全局状态管理器。

推荐：
- `stateManager.js` 统一管理状态
- `eventBus.js` 统一发送跨应用事件
- `saveManager.js` 统一存档
- UI 模块禁止直接修改其他模块内部状态

所有聊天、邮件、网页、线索必须 JSON 化。

## 10. 技术实现原则
1. 优先模块化，而不是追求一次性完成。
2. 先完成交互骨架，再补内容资产。
3. 桌面应用和剧情数据解耦。
4. 所有关键对象使用唯一 ID。
5. 页面允许后续扩展到第二、三、四幕。
6. 不允许为第一幕写死一个不可扩展的临时代码结构。
