# 《暗潮》开发文档 04：可追溯开发规范

> 目标：保证项目后续扩展时可维护、可回溯、模块化、低 token 消耗，并适合长期使用 Codex / AI 协作开发。

# 1. 核心原则

1. 剧情内容与界面逻辑分离。
2. 所有可变内容数据化。
3. 所有线索、页面、消息、邮件、图片必须有唯一 ID。
4. 每个功能模块职责单一。
5. 每完成一个节点必须记录进度。
6. 所有新增内容都要写明：
   - 属于哪一幕
   - 属于哪个阶段
   - 服务什么目的
7. AI 修改代码时只提供当前模块必要上下文。
8. 禁止一次性让 AI 重写整个项目。

# 2. ID 命名规范

## 2.1 通用格式

```text
[类型]_[幕]_[阶段]_[序号]
```

## 2.2 示例

```text
MAIL_A1_C_001
CHAT_A1_B_003
IMG_A1_H_002
CLUE_A1_005
PAGE_A1_BROWSER_004
```

## 2.3 状态 Flag

推荐：

```text
FLAG_A1_MOM_MSG_READ
FLAG_A1_MAIL_XIAOA_OPENED
FLAG_A1_NEWS_FOUND
FLAG_A1_AW_FOUND
FLAG_A1_SS_FOUND
```

# 3. 类型前缀建议

```text
MAIL    邮件
CHAT    聊天内容
CONTACT 联系人
IMG     图片
PAGE    网页
CLUE    线索
FILE    文件
SCENE   场景
EVENT   事件
FLAG    状态
AUDIO   音频
UI      界面元素
```

# 4. 数据文件规范

不同内容必须独立管理。

推荐：

```text
/data
  contacts.json
  chats.json
  mails.json
  browser_pages.json
  files.json
  images.json
  clues.json
  flags.json
  events.json
```

禁止把所有剧情文本塞进一个 JS 文件。

# 5. 数据对象必须包含的字段

推荐基础结构：

```json
{
  "id": "MAIL_A1_C_001",
  "title": "小A旧邮件",
  "act": 1,
  "phase": "C",
  "source": "mail",
  "purpose": "提供时间与地点核心线索",
  "unlockCondition": [],
  "relatedFlags": [
    "FLAG_A1_MAIL_XIAOA_OPENED"
  ],
  "notes": "第一幕关键邮件"
}
```

对于不同对象可增加专属字段，但基础元数据尽量保留。

# 6. 状态管理规范

## 6.1 Flag 分类

### 剧情推进 Flag
表示玩家是否完成关键推进。

### 线索发现 Flag
表示玩家是否发现某个线索。

### 页面访问 Flag
表示某页面是否被打开。

### 应用使用 Flag
表示某应用功能是否被使用。

### 防卡提示 Flag
表示某个提示是否已经出现。

## 6.2 第一幕示例

```text
FLAG_A1_MOM_MSG_TRIGGERED
FLAG_A1_MOM_MSG_READ
FLAG_A1_XIAOA_MISSING_KNOWN
FLAG_A1_MAIL_XIAOA_OPENED
FLAG_A1_DATE_20200419_KNOWN
FLAG_A1_NEWS_FOUND
FLAG_A1_ROUTE_INFO_FOUND
FLAG_A1_AW_FOUND
FLAG_A1_AW_PHOTO_TAKEN
FLAG_A1_BU_FOUND
FLAG_A1_SS_FOUND
```

## 6.3 Flag 规则

1. 一个剧情点只使用必要 Flag。
2. 不重复创建语义相近状态。
3. 每个 Flag 必须有说明。
4. 不允许组件自己创建临时隐性剧情状态。
5. 剧情状态必须能被存档。
6. 状态命名一旦进入正式版本，不随意修改。

# 7. 模块职责规范

## 7.1 模块边界

```text
wechatApp.js
```
只处理微信。

```text
mailApp.js
```
只处理邮箱。

```text
browserApp.js
```
只处理浏览器。

```text
windowManager.js
```
只处理窗口行为。

```text
stateManager.js
```
只处理全局状态。

```text
saveManager.js
```
只处理存档与读取。

## 7.2 禁止行为

禁止：
- 微信模块直接改邮箱内部变量
- UI 组件直接修改剧情 Flag
- 多个文件维护同一份数据
- 剧情文本直接硬编码在 DOM 中
- 同一个功能散落在多个无关模块
- 为临时需求复制粘贴大段逻辑

跨模块统一通过：
- `stateManager`
- `eventBus`

通信。

# 8. 素材命名规范

推荐：

```text
act1_desktop_bg_01.png
act1_wechat_contact_mom_01.png
act1_wechat_contact_xiaoyue_01.png
act1_cave_wall_aw_01.png
act1_temple_bu_01.png
act1_news_missing_01.jpg
```

要求：
- 带幕号
- 带用途
- 可读
- 可替换
- 不允许 `1.png`
- 不允许 `新建文件(2).png`
- 不允许随机字符串作为正式素材名

# 9. 页面命名规范

推荐：

```text
page_act1_search_chickenridge_01.html
page_act1_news_missing_01.html
page_act1_wiki_chickenridge_01.html
page_act1_forum_hiking_01.html
```

如果页面数据化渲染，则页面本体可统一，数据仍必须使用独立 ID。

# 10. 剧情内容可追溯规范

每条正式内容都必须回答四个问题：

1. 它是什么？
2. 它属于哪一幕哪一阶段？
3. 它推进什么信息？
4. 如果删掉它，会损失什么？

示例：

```markdown
ID: MAIL_A1_C_001

内容：
小A于 2020.04.19 发来的邮件

所属：
第一幕 / 阶段 C

作用：
提供调查时间锚点与地点

删除影响：
玩家失去核心调查起点，第一幕主线无法成立
```

# 12. TODO 管理规范

推荐使用：

```text
/docs/todo.md
```

只保留当前待开发事项。  
完成后移动到 `progress_log.md`，避免 TODO 无限膨胀。

# 13. CHANGELOG 规范

正式功能变化维护：

```text
/docs/changelog.md
```

格式：

```markdown
## v0.1.3

### Added
- 新增母亲实时微信消息触发

### Changed
- 小A邮件从默认列表第一页移动到旧邮件区域

### Fixed
- 修复最小化窗口后无法从任务栏恢复的问题
```

# 14. AI / Codex Token 节约规范

这是长期开发中非常重要的一部分。

## 原则 1：一次只改一个模块

例如：

> 只修改 `wechatApp.js`，不要修改其他模块。

## 原则 2：只提供必要上下文

修改微信时提供：
- `wechatApp.js`
- `chats.json`
- `contacts.json`
- 相关 Flag
- 当前开发目标

不要提供四幕全部剧情。

## 原则 3：用 ID 引用，不重复粘贴全文

例如不要重复给 AI 完整剧情，而是说：

> 调用 `MAIL_A1_C_001`。

详细内容已经保存在数据文件里。

## 原则 4：规范文件作为长期规则

AI 每轮只需要读取：

```text
traceable_dev_spec.md
```

中的必要章节。

不用每次重新解释：
- 命名
- 状态
- 模块化
- 开发原则

## 原则 5：禁止一次生成整个项目

不要这样：

> 把整个《暗潮》网页游戏完整开发出来。

建议这样：

> 完成 Windows 桌面的窗口系统，不实现任何剧情内容。

之后：

> 完成微信联系人列表和聊天窗口。

之后：

> 接入第一幕母亲消息。

# 15. AI 修改代码标准指令模板

推荐以后直接使用：

```markdown
任务：
完成 [具体功能]

允许修改：
- src/modules/xxx.js
- data/xxx.json

禁止修改：
- 其他模块
- 全局目录结构
- 已有 ID

必须遵守：
- docs/traceable_dev_spec.md
- 当前状态 Flag 规范

完成后：
1. 列出修改文件
2. 列出新增 ID
3. 列出新增 Flag
4. 更新 progress_log.md
5. 不做任务范围之外的重构
```

# 16. 开发优先级规范

## 第一优先级
- 桌面壳层
- Window Manager
- State Manager
- Save Manager
- 微信
- 邮箱

## 第二优先级
- 浏览器
- 搜索系统
- 记事本
- 资源管理器
- 照片查看器

## 第三优先级
- 鸡头岭场景
- 山洞
- 破庙
- 照片编辑谜题
- 防卡提示

# 17. 第一幕完成定义（Definition of Done）

第一幕只有同时满足以下条件才算完成：

- [ ] Windows 11 桌面可正常操作
- [ ] 窗口系统稳定
- [ ] 微信联系人与历史聊天可查看
- [ ] 母亲消息可按状态触发
- [ ] 邮箱包含真实噪音内容
- [ ] 小A关键邮件可通过合理方式找到
- [ ] 浏览器可以进行多个关键词搜索
- [ ] 搜索结果存在强相关、弱相关、无关内容
- [ ] 记事本可以记录线索
- [ ] 桌面状态可以存档恢复
- [ ] 鸡头岭场景可正常进入
- [ ] 山洞可发现 A.W
- [ ] 破庙可发现“补”
- [ ] 照片编辑可发现双S
- [ ] 第一幕所有关键 Flag 可正确保存
- [ ] `progress_log.md` 已更新
- [ ] 所有正式资源拥有规范 ID

# 18. 最终开发原则

**写实优先，剧情其次显性。**

玩家应感受到：

> 我是在一台真实电脑里自己找到了一件不对劲的事情。

而不是：

> 游戏给了我一台 Windows 皮肤的解谜菜单。
