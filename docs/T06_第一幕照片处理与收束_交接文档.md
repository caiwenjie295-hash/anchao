# 《暗潮》T06 第一幕照片处理与收束交接

## 完成范围

第一幕已完成 A–K。玩家在阶段 I 下山后，从资源管理器打开已拍摄照片；山洞照片可调整曝光、阴影、对比度并缩放。三项参数达到合理范围后，玩家主动检查画面中的双 S 十字符号，进入阶段 K 并在记事本看到第一幕线索汇总。玩家可先阅读记录，再点击“整理思绪，继续”进入幕末并写入完成 Flag。

## 关键入口

- 离线试玩：双击项目根目录的 `暗潮.html`，无需启动服务。
- 重新生成离线文件：运行 `npm run build:offline`。
- 重玩：桌面和幕末均提供共用清零组件；点击“清零进度”后选择“确认清零”，从阶段 A 开始并清空全部持久化进度。

## 关键数据与状态

- 照片数据：`data/photos.json`；现场照片固定为 `IMG_A1_H_003` 与 `IMG_A1_I_004`。
- 照片 UI：`src/modules/explorer/ExplorerApp.tsx` 与 `src/modules/photos/PhotosApp.tsx`。
- 阶段控制器：`src/story/act1PhaseJKController.ts`；幕末完成 API：`StateManager.finishFirstAct()`。
- 幕末数据与界面：`data/act1_ending.json` 与 `src/components/Act1Ending.tsx`。
- 新增 Flag：`FLAG_A1_PHOTO_EDIT_OPENED`、`FLAG_A1_SS_FOUND`、`FLAG_A1_SS_CLUE_RECORDED`、`FLAG_A1_COMPLETE`。
- 照片编辑、缩放、已查看符号状态位于 `modules.photos`，并随存档和完整清零处理。

## 维护约束

- 照片中的 A.W 与普通游客留言由山洞热点数据复用，修改现场留言时应同步检查照片效果。
- 双 S 仍应由玩家主动检查，不应在参数达到阈值时自动完成剧情。
- 现有 CSS/SVG 仅是可观察的谜题原型。替换正式场景或照片素材时保留 ID、阶段和阈值体验，并验证暗处符号仍可辨认。

## 验证记录

- `npm test`：13 个测试文件、48 项测试通过。
- `npm run build`、`npm run build:offline`：通过。
