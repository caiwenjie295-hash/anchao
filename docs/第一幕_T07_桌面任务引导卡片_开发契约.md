# 《暗潮》第一幕 T07 桌面任务引导卡片开发契约

> 状态：权威执行契约
> 基线：2026-09-18，第一幕 A–K 已可完整试玩
> 角色：Terra 实现者；主任务集成与验收
> 规则：执行者可以读取但不得修改本契约

## 1. 目标与范围

### 目标

在现有私人电脑桌面加入一张可折叠的“当前待办”卡片。卡片必须根据真实存档状态显示当前目标、分步完成情况和进入相关应用的按钮，让第一次游玩的玩家知道下一步从哪里开始，同时保留主动调查和观察的空间。

### 必须交付

- 数据驱动的第一幕桌面引导定义与纯函数求值器。
- 桌面待办卡片组件，支持展开/收起、完成状态和一个主要行动按钮。
- 将卡片接入 `src/App.tsx` 的桌面层。
- 宽屏、窄屏、键盘焦点与减少动态效果兼容。
- 数据求值与关键组件行为测试。

### 非目标

- 不改变 A–K 剧情、Flag、阶段控制器、照片阈值或结局条件。
- 不给 G–I 场景页增加新 UI；场景内继续使用既有底部操作区。
- 不增加任务奖励、成就、地图、提示次数、跳过谜题或自动推进。
- 不生成新图片，不增加依赖，不重做桌面或应用视觉。

### 延后事项

- 玩家手动创建待办：延后，不实现。
- 多幕通用任务系统：延后；本次接口保持可扩展，但只交付第一幕数据。
- 卡片展开状态跨存档持久化：延后；本次使用组件本地状态。

## 2. 冻结产品规则

- 卡片不是“任务列表应用”，而是桌面上的调查便笺；标题固定为“当前待办”。
- 宽屏（建议 `min-width: 900px`）默认展开；窄屏默认收起为紧凑按钮，玩家可手动展开。
- 卡片可覆盖桌面墙纸并位于普通窗口之上，但必须可收起；不得遮挡任务栏。窄屏展开后宽度不得超过视口。
- 仅在桌面渲染。`sceneOpen === true` 时随桌面隐藏；`FLAG_A1_COMPLETE === true` 时由幕末页取代，不再显示。
- 每次只展示一个调查组；组内最多 3 个步骤。已完成步骤保留并打勾，首个未完成步骤标为当前步骤。
- 主要行动按钮只打开或聚焦相关应用，不得自动打开邮件、网页、照片、聊天或替玩家完成任何 Flag。
- 卡片不得显示确切搜索词、场景热点位置、照片滑杆数值或尚未发现的“双 S”名称。
- 视觉方向：Windows 私人桌面上的一张偏暖白色调查便笺，沿用当前蓝灰系统色，仅用一处低饱和琥珀色标识“当前”；不引入新全局设计系统。
- 标志性动作：任务完成时，步骤左侧由空心圆变成细线勾选，并让“当前”标记平稳移到下一条；遵守 `prefers-reduced-motion`。
- 卡片 UI 状态不是剧情状态，不写入 `AppState`、LocalStorage 或新 Flag。

## 3. 冻结引导链

引导组按下表顺序选择：前置条件全部满足、完成条件尚未全部满足的第一组。

| 引导 ID | 前置条件 | 完成条件 | 玩家可见目标 | 步骤与行动入口 |
|---|---|---|---|---|
| `GUIDE_A1_001` | 无；阶段 A/B | `FLAG_A1_XIAOA_MISSING_KNOWN` | 看看有没有新的消息 | ① 打开微信，留意新消息 → 微信；② 读一读母亲发来的消息 → 微信 |
| `GUIDE_A1_002` | `FLAG_A1_XIAOA_MISSING_KNOWN`；阶段 B/C | `FLAG_A1_MAIL_XIAOA_OPENED` | 找出小A最后留下的线索 | ① 在邮箱置顶区域找到小A的旧邮件 → 邮箱；② 打开邮件，确认时间和地点 → 邮箱 |
| `GUIDE_A1_003` | `FLAG_A1_MAIL_XIAOA_OPENED`；阶段 C/D/E | `FLAG_A1_NEWS_FOUND` + `FLAG_A1_ROUTE_INFO_FOUND` | 核对鸡公岭的公开信息 | ① 找到与失踪有关的旧报道 → 浏览器；② 确认徒步路线的长度与难度 → 浏览器 |
| `GUIDE_A1_004` | `FLAG_A1_TEMPLE_PHOTO_TAKEN`；阶段 I/J | `FLAG_A1_SS_FOUND` | 整理鸡公岭现场照片 | ① 从资源管理器打开山洞照片 → 资源管理器；② 调整画面，让暗处细节变得可辨 → 照片；③ 检查画面中新出现的痕迹 → 照片 |
| `GUIDE_A1_005` | `FLAG_A1_SS_FOUND`；阶段 K | `FLAG_A1_COMPLETE` | 整理已经找到的线索 | ① 确认新线索已记入记事本；② 回到照片，点击“整理思绪，继续” → 照片 |

步骤完成规则：

- 微信步骤分别使用 `FLAG_A1_MOM_MSG_TRIGGERED`、`FLAG_A1_XIAOA_MISSING_KNOWN`。
- 邮箱步骤分别使用 `FLAG_A1_MAIL_XIAOA_FOUND`、`FLAG_A1_MAIL_XIAOA_OPENED`。
- 浏览器步骤分别使用 `FLAG_A1_NEWS_FOUND`、`FLAG_A1_ROUTE_INFO_FOUND`。
- 照片第一步使用 `modules.photos.openedPhotoIds` 是否包含 `IMG_A1_H_003`。
- 照片第二步必须复用 `isSymbolVisible(adjustment)`，不得复制或更改阈值。
- 照片第三步使用 `FLAG_A1_SS_FOUND`。
- 收束第一步使用 `FLAG_A1_SS_CLUE_RECORDED`，第二步使用 `FLAG_A1_COMPLETE`。
- 若存档状态不满足任何引导组，求值器返回 `null`，组件不渲染。

## 4. 共享接口

| 接口 | 生产者 | 消费者 | 冻结约定 |
|---|---|---|---|
| `data/task_guides.json` | Terra | `taskGuideData.ts` | `schemaVersion: 1`；剧情文案和步骤入口只放数据文件 |
| `getCurrentTaskGuide(state)` | Terra | `DesktopTaskCard` / 测试 | 输入 `AppState`，返回只读视图模型或 `null`；不得产生副作用 |
| `DesktopTaskCard` | Terra | `App.tsx` | props 至少包含 `state` 与 `onOpenApp(appId)`；组件不得直接推进剧情 |
| 行动入口 | 现有桌面 | 卡片 | 调用现有 `StateManager.openApp(appId)`，由窗口系统负责打开/聚焦 |

建议视图模型包含：`id`、`title`、`summary`、`completedCount`、`totalCount`、`steps[]`、`actionAppId`、`actionLabel`。字段可以补充，但不得改变上述产品行为。

## 7. 执行与验收顺序

1. Terra 读取本契约和 `维护导航.md`，只在独占路径内实现。
2. Terra 先完成数据求值器测试，再接入组件和样式。
3. Terra 运行四项验证并提交报告，不修改本契约或导航文档。
4. 主任务核对实际变更路径、引导文案、剧情不剧透和窗口遮挡行为。
5. 主任务在宽屏与窄屏做视觉验收，并运行组合验证。
6. 主任务更新导航、进度、待办和变更记录。

## 8. 冲突处理

- 命名冲突：以本契约为准，不在实现中私自改名。
- 需要修改核心状态或控制器：停止该改动并报告，由主任务决定是否扩展范围。
- 既有脏文件：保留并绕开，禁止重置或覆盖。
- 数据不足：返回 `null` 或保留最小可用卡片，不得用隐性 Flag 补洞。
- 契约缺陷：只有主任务可以修改本契约。
