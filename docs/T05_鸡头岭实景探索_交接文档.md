## 2. 运行入口与核心文件

- 总入口：`src/App.tsx`
  - `sceneOpen` 决定显示桌面、黑屏转场或场景。
  - 场景开启时桌面保留状态，但被隐藏并设为 `inert`，不会参与键盘焦点。
- 场景 UI：`src/scenes/act1/Act1SceneExperience.tsx`
  - `SceneTransition`：阶段 F 的黑屏转场。
  - `SceneView`：数据化场景、热点、观察详情、相机和继续/下山。
  - `Hotspot`：按百分比坐标定位的可聚焦按钮。
- 场景数据适配与校验：`src/data/sceneData.ts`
  - `sceneById`、`hotspotById`、`hotspotsBySceneId`。
  - `validateSceneData()` 校验场景顺序、图片/Flag 引用、坐标、普通热点和唯一关键标记。
- 剧情控制器：`src/story/act1PhaseGHIController.ts`
  - `Act1PhaseGHIController` 是阶段 G/H/I 和五项正式 Flag 的唯一写入者。
- 状态 API：`src/core/stateManager.ts`
  - `startJourney`
  - `enterScene`
  - `inspectSceneHotspot`
  - `captureScenePhoto`
  - `finishJourney`
- 存档恢复：`src/core/saveManager.ts` 的 `hydrateState()`。
- 场景样式：`src/styles.css` 中搜索 `M4:`、`.journey-transition`、`.act1-scene`、`.scene-hotspot`。

## 4. 状态、事件与门槛

### 持久化状态

```text
modules.scene.journeyStarted
modules.scene.currentSceneId
modules.scene.visitedSceneIds
modules.scene.inspectedHotspotIds
modules.scene.capturedPhotoIds
```

- T05 正常结束时：`journeyStarted=false`、`currentSceneId=null`、`game.phase='I'`。
- 已拍照片仍保留在 `capturedPhotoIds`，不得在回桌面时清空。
- 旧存档自动补默认场景状态；损坏或未知 `currentSceneId` 回退桌面。

### 公开事件

```text
journey:started
scene:entered
scene:hotspot-inspected
scene:photo-captured
journey:finished
```

### 正式 Flag

```text
FLAG_A1_AW_FOUND
FLAG_A1_AW_PHOTO_TAKEN
FLAG_A1_TEMPLE_FOUND
FLAG_A1_BU_FOUND
FLAG_A1_TEMPLE_PHOTO_TAKEN
```

门槛固定为：

- 未检查 A.W：不能拍山洞照片。
- 未拍山洞照片：不能进入破庙。
- 未检查“补”：不能拍破庙照片。
- 未完成破庙三项 Flag：不能下山。
- `StateManager` 同时执行顺序校验；不要只依赖按钮的 disabled 状态。

## 5. T06 对接约束

后续若恢复 T06，必须遵守：

1. 从 `modules.scene.capturedPhotoIds` 读取已拍照片，不另建第二份照片完成状态。
2. 只有存在 `IMG_A1_H_003` 时，资源管理器/照片查看器才显示山洞照片。
3. `IMG_A1_H_003` 是照片编辑与双 S 谜题的唯一输入；不要把双 S 写回 T05 场景或原始留言墙。
4. `IMG_A1_I_004` 作为“补”的证据可查看，但不能在第一幕解释含义。
5. T06 从 `game.phase === 'I'` 开始，完成照片处理后再进入 J/K；不要修改 T05 的 G/H/I Flag 语义。
6. 正式美术替换必须保留 `data-asset-id` 与现有 ID，不把剧情内容硬编码进 React 组件。

## 8. 常用维护操作

- 调整场景文案或顺序：编辑 `data/scene_act1.json`，同步检查 `validateSceneData()` 的冻结顺序。
- 调整热点位置/观察文本：编辑 `data/scene_hotspots.json` 的 `position` 与 `observation`。
- 替换场景美术：保留图片 ID，在后续资源映射层替换；不要改变 Flag 或热点 ID。
- 修改剧情门槛：先核对 `game/03` 和 M4 契约，再统一修改场景数据与控制器测试。
- 回归验证：运行 `npm test`，然后运行 `npm run build`。
