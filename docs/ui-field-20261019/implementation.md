# UI-FIELD-20261019 实施记录

## 启动资源与章节续玩

启动清单 schema 2 的 `resources` 扁平列表是唯一文件及 SHA-256 清单，`groups` 只标记同一文件依赖哪些章节，避免跨幕素材重复计入。新游戏前台请求 `shared + act1 + act2`，第三、四幕在后台低优先级预取；继续游玩与章节重玩按兼容归一后的存档目标请求 `shared + 当前幕`，当前幕资源能提升排队或运行中的后台任务。前台等待可取消、失败可在选章内重试；后台失败只记入该幕资源状态，不拦首屏。没有 Web 启动器的开发与 `file:` 测试也能使用章节就绪接口。

第二幕与第三幕显式带上会跨幕展示的旧素材：A2 含 `IMG_A1_I_001`、`IMG_A1_I_002`、`IMG_A1_I_003`、`IMG_A1_H_003`；A3 含 `IMG_A1_I_001` 与 `IMG_A1_I_003`。新游戏首次三组去重后需载入 69 项、23,291,240 字节；整份清单共 275 项、83,465,160 字节。按合法续玩目标计算，A3 的 `shared + act3` 为 134 项、51,226,298 字节；A4 的 `shared + act4` 为 96 项、22,359,776 字节。这些数字取自本轮生产构建生成的预载清单。

## 剧情提示与田野调查册

第一幕 phase F 保留徒步网页和原有剧情状态。读到路线资料不会自动开始徒步；玩家可点“整理线索 / 准备出发”查看确认页，再选“前往鸡公岭”，也可选“暂不出发，返回资料”。取消会回到资料页并恢复原触发按钮焦点，没有新增存档字段。

搜索步骤在任务标签和当前搜索入口直接写出可用关键词：第一幕分别提示“XX县失踪”和“鸡公岭徒步”，第二幕 T01 提示“鸡公岭 补”，并可使用已经发现的“双S 十字”。说明文案补充应核对的报道或路线内容，不重复关键词。T06 的机构提示只在现有发现条件成立后出现；人物名仍以已读来源为前提。搜索数据、Flag 与解锁条件未变。

T02 桌面保留照片与人物索引并列、口述内容在旁的布局；窄屏顺序为照片、人物索引、当前口述，44px 人物入口紧跟照片，避免长对话把名单推到远处。T05 使用 01 方案的浅灰白纸面和清晰层级，蓝灰用于路线和操作，朱砂作为少量标记；旧纸泛黄集中在两份实际材料原件。地图保留室外与室内路线，选择地点后手机会将当前现场标题滚回可见区，不改焦点或剧情状态，并遵循系统 reduced-motion 设置。

学校进度将“已读材料”与“选作来源”分开统计，访问地点不计入证据。读记录、选至少两种来源及选择暂定判断继续走既有领域门槛；双 S 比对仍使用第一幕真实照片。两张新手写原件均可放大并提供准确转录，图片加载失败时保留转录入口；切换素材会重置各自失败状态。学校弹窗高于章节入口，Tab/Shift+Tab 在材料弹窗内循环；原件使用原生 dialog，并由其自身处理 Escape。

存档仍使用 schema 13、现有 Flag、StateManager、BGM 与旧图登记。独立 MemoryStorage 种子和注入步骤见 [fixture/README.md](fixture/README.md)；seed 由合法状态/控制器路径构造，不添加产品识别分支，也不接触玩家存档。
