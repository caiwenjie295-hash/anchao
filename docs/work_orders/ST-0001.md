> 状态：权威执行工单
> 基线：`22bd206`（`main`）
> 唯一写入者：Codex
> 分支：`codex/ST-0001-story-transitions`

## 目标

排查第一幕 A–K 与第二幕 T01–T06 的实际推进节点，补齐玩家能读懂“刚发生什么、为什么继续”的黑底白字短转场；新游戏开屏增加序幕简介。

## 冻结接口

- 转场正文、标题、触发阶段与条件保存在 `data/story_transitions.json`，不写死在 UI。
- 现有阶段、Flag、笔记、谜题、资源 ID 与剧情结论不变；第一幕 F→G 的山路转场和 K 幕末黑屏继续复用，只增补文字。
- 新增 `modules.storyTransitions.seenIds: string[]`，存档 schema 5→6，键仍为 `anchao.save.v1`。仅 `StateManager.acknowledgeStoryTransition(id)` 可写；损坏 ID 清洗，旧 schema 1–5 根据当前阶段标记已走过的转场。
- 开屏序幕只在新游戏阶段 A 未确认时显示；清零后重新显示。阶段转场需玩家主动继续，不自动计时；重载后未确认的当前转场继续显示。
- 覆盖实际推进：母亲消息已读、旧邮件、网页调查、山洞、破庙、下山、照片处理、第二幕 T01–T06。阶段 D 为生活内容层，当前没有独立的阶段推进动作，审计记录需明确；F→G 和 K 已有独立黑屏，不叠加双转场。
- T05/T06 文案不得提前披露 T07 的破庙影像结论；消防栓不作提示。

## 验收标准

- 新游戏先见黑底白字序幕，说明主角处境和从电脑探索的起点；点击后进入原桌面。
- 真实推进节点显示短转场，文案总结已知信息并提示下一调查方向，不提前泄露下一阶段答案。
- 读过的转场不在重载后重复；未读转场在重载后保留；清零后序幕恢复；旧存档不倒放已完成剧情。
- 全部转场可键盘操作、焦点留在当前层；PC 宽屏全屏体验正常，窄屏精修按用户要求延后。
