## 3. 检查结果：原因、影响和代码位置

本节依据用户截图、当前源码和原始照片检查。未把本次检查冒称为完整浏览器通关测试；外部 Agent 必须按第 10 节复现并验收。

### 3.1 图片一：照片被缩放，双 S 没跟着照片变换

来源版本 `src/act2/t07Finale.css`：

- `.t07-frame` 使用宽容器和固定/最小高度。
- `.t07-frame--image > img` 使用绝对定位、100% 宽高及 `object-fit: contain`。
- 放大规则仅对 `img` 应用 `scale(2.3)` 和 `transform-origin:86% 86%`。
- `.t07-finale__photo-symbol` 独立相对外框以 `right:7%; bottom:9%` 定位。

在 `T07Investigation.tsx` 的 `FrameVisual` 中，图片与双 S 是同一外框内的不同元素，只有图片缩放，符号没有共享照片的实际内容边界与变换。contain 的空带又参与了容器定位，因此出现截图中的“局部照片在左，符号在右侧灰底”。

另一个问题：`photoZoom = photoZoomed || photoConfirmed` 把“已经发现证据”和“当前是否放大”绑在一起，确认后难以恢复完整照片。

### 3.2 图片二：4:3 素材被放进过宽的定高框

- `IMG_A2_T07_005.jpg` 与 `石庙外景1.png` 的实际图像均为 1448×1086，即 4:3。
- 对照列宽较大，而 `.t07-finale__compare-side .t07-frame` 固定最低高度、`img` 又以 contain 放入这个宽框。
- 图片实际显示宽度由高度×4/3 决定，剩余面积变成 `#8e9895` 灰绿色空带。
- 这不是原图本身有灰边。只把背景改白、把 contain 改回 cover，或横向拉伸图片，都不能作为修复。

### 3.3 外景对照的现有逻辑问题

`src/scenes/act2/T07Investigation.tsx` 与对应 stateManager：

1. 进入对照页就显示小月“我觉得就是一个东西”的结论，即使选中错误候选也先出现肯定台词。
2. `!zoomLeft || !zoomRight` 阻止核对，把工具操作当成证据条件。
3. “放大”按钮实际是 toggle，放大后文字仍为“放大”，再次点击反而恢复。
4. 候选按 `video.keyFrames` 的登记顺序展示，不一定按玩家截图顺序；正确候选位于该数据列表首位。
5. 选择一个特征后先调用 `compareAct2T07TempleFrame`，再点 `confirmAct2T07TempleFrame`，重复确认同一结论。
6. 地点综合判断与进山操作放在另一个区域，成功后下一步不够连续。
7. 放大图 `IMG_A2_T07_006` 当前映射到同一个 `IMG_A2_T07_005.jpg`；不能假装它是一张额外的高精度证据。

### 3.4 配色不是单个背景问题

- T07 页面背景 `#e7e4dc`，卡片 `#f7f6f0`，按钮/选中项偏灰绿，正文混用大量 Georgia/斜体。

### 3.6 第三幕图片比例失真：已定位共用显示链，仍须实测根因

- `src/scenes/act3/Act3Investigation.tsx` 主调查图使用 `PhotoViewport`。`src/components/PhotoViewport.tsx` 在 onLoad 读取 naturalWidth/naturalHeight，以 contain 算法计算内容平面尺寸，理论上应保持比例；因此不能仅看见 `object-fit:fill` 就断言全部根因。
- `src/components/photoViewport.css` 的图片为 width/height 100%、object-fit:fill。只要内容平面尺寸过期或错误就会被拉伸，需要检查实际 DOM 尺寸及 CSS 覆盖。
- 该组件在内部根节点上使用 `key={sceneKey}`，观察 frame 的 effect 却仅运行一次。镜头切换可能替换被观察的 DOM，ResizeObserver 仍指向旧节点；imageSize 也没有按 imageUrl 显式失效。以上是需验证的风险点，不能直接写成已复现结论。
- `.act3-investigation__temple-compare img` 另有固定 160px 高度和 cover，属于可能裁切证据的另一条显示路径，也必须纳入检查。
- 用户报告“第三幕全都被压扁”，本工单按全幕逐图验收，不能只修改一个镜头后结案。具体实现与验收见第 16 节。

## 4. 工作包 A：图片与标记在同一坐标系中

### 4.1 结构要求

将“视口”和“图像内容平面”分开。图片本体与属于照片的标记在同一个内容平面内，再一起变换：

```text
证据查看器（控制显示范围、裁切与边界）
  图像内容平面（尺寸等于实际照片显示尺寸，统一缩放/平移）
    原始照片
    双 S / 玩家选区 / 图内证据标注
  查看器工具栏（不跟随照片变换）
```

- 双 S 锚点使用原图归一化坐标，不使用页面宽度百分比、外框 right/bottom 或屏幕固定位置。
- 缩放与平移对图片和符号共用同一 transform，尺寸变化后重新按图像几何计算。
- 若仍使用 contain，必须扣除实际图像外的空带；更推荐让内容平面本身按原图比例建立，不让空带成为坐标的一部分。
- 图内标记必须被图像边界裁切，不能画到图外；工具栏、关闭、导航始终在变换层外。
- 不要为本次修复把 UX-234 已固定在图外的导航再次移回照片内部。用户本次所说“标记在图片里”指照片中的双 S/证据标注。

### 4.2 双 S 的具体表现

- 原图为 `src/第二幕/IMG_A2_T07_001.jpg`，右下角已有模糊区域；继续在这个原图区域表现线索，不把符号移动到人物、锦旗或凭空增加的新场景。
- 开发者对实际原图确认锚点，并在数据中记录 x/y、尺寸及说明；不要照抄旧容器 `right:7%;bottom:9%`。
- 复用 `DoubleSSymbol` 的轮廓，使用局部样式表现照片中的低清标记，避免成为过大、锐利的悬浮 UI 图标。
- 完整照片与局部放大始终是同一张图。图内符号与背景的相对位置保持一致。
- “查看右下角”把目标区域带到视口中心，放大值可控；允许还原全图、缩小、再次放大。
- 缩放、滚动、窗口 resize 不写剧情 Flag。玩家明确选择“记录这个标记”后才调用已有证据动作。
- 已记录状态不强迫保持放大；刷新后可正常看全图，并显示“已记录”。
- 不要求新绘制照片，不重生成任何人物照片。本轮以显示与叠加逻辑修复为主。

### 4.3 几何验收

- 每个支持视口下，符号中心都在实际照片内容矩形内，且对应同一原图位置。
- 使用变换矩阵/图像矩形进行坐标换算；桌面误差建议不超过 2 CSS px，窄屏不超过 3 CSS px。
- 最大缩放、平移到边缘、复位、窗口变化后仍符合要求。
- 测试必须计算实际图片内容区域；contain 图片的 `<img>` 元素 bounding box 可能包含空白，不能只断言符号位于 `<img>` 标签外框内。

## 5. 工作包 B：两图对照的版式与查看工具

### 5.1 默认布局

- 宽屏为两列等宽，列内部照片按 4:3 完整展示，容器随图片自然比例确定高度；删除造成不匹配的固定矮高度。
- 对照工作区建议最大宽度 1120–1280 CSS px，居中；列间距 16–24 px。外部正常页面留白允许，图片内部大面积填充色不允许。
- 当前两张 4:3 原图在默认视图中，应由图片实际内容填满图框内部，边框之外仅保留常规布局间距。
- 视口高度不够时允许页面纵向滚动，不通过裁掉证据或压扁图片适配。
- 低于约 760 px 时上下排列，保留“视频截图”和“第一次进山照片”的来源标签；不得出现页面横向溢出。
- 未来遇到不同宽高比素材，按各图自然比例显示，接受列内正常对齐差异，不强行拉伸；需要共同视口时使用中性细小留白并解释来源差异。

### 5.2 查看工具

- 使用“放大 / 缩小 / 还原全图”或明确百分比，禁止一个永远写“放大”的 toggle 同时承担缩小。
- 两侧可以独立缩放、平移，所有工具操作都不是通关门槛。
- 可打开大图检查并返回对照工作区；关闭后保留选中的候选、标记区域和判断依据。
- 不做强制叠图配准：两张图机位不同，不应假定像素一一对齐。
- 图注、来源和候选时间码不叠在关键证据上；弹窗关闭按钮始终可见。

## 7. 工作包 D：外景对照的新交互合同

### 7.1 目标流程

```text
已有候选截图
    ↓ 选择一张（按截图时间/顺序，不能默认优先挑正确答案）
并排查看视频截图与首次进山照片
    ↓ 自由观察，可选放大，不要求画框或逐项操作工具
选择可见的对应依据
    ↓ 一次“记录这处对应”
成功：保存对应关系，显示事后对话与结论摘要
失败：说明证据不足，保留当前选择，允许调整
    ↓ 合影标记也已记录时
综合地点判断 → 主动商量再次进山
```

缩放是查看工具，不计入这个状态流程。综合地点判断与再次进山仍是不同层级的剧情行动，保留主动选择；删除的是同一图片比对结论的二次盖章。

### 7.2 候选与空状态

- 无截图：显示“还没有保存可核对的画面”，提供“去视频中截取画面”的直接入口，返回后自动回到对照工作区。
- 一个候选时可默认选中，但不默认标记区域、不默认选理由。多个候选按时间或截图顺序排列，不按 `supportsExteriorMatch` 排序。
- 候选只展示缩略图、时间码与中性描述；不要在缩略图上写“正确破庙帧”。内部判定字段不能用于提前高亮答案。
- 换候选后清除上一张的临时判断反馈；可按候选保留各自草稿，但不能把正确帧的依据和成功状态借给错误帧。
- 00:06.8–00:08.6 的 `FRAME_A2_T07_001` 是现有有效建筑片段；山路、受访者仍是合法候选但不能直接确认同一建筑。

### 7.3 对应依据与自然观察

- 保留可用的候选截图和特征选择；不新增强制画框、拖线或精确点选建筑的通关步骤。
- 两图完整并排，允许查看局部；任何选框/标记都只是辅助，使用原图坐标并随照片变换。
- 当前原图能观察到石砌开口、上方横向构件与左侧斜靠石板的相对位置，开发者须对原图校准，不虚构特征。
- “建筑开口与左侧斜靠石板相对位置相符”等有辨识度依据可支持判断；“都有树木/山路”仅说明环境相似，应反馈不足。
- 至少保留一个合理但不充分的备选依据，正确选项不要靠明显更长、更专业的措辞暴露。
- 不把“塌落的石檐”当作无需检查的事实，按照片实际可见内容描述。
- 选择和提交都可用键盘、触屏完成。未使用缩放或辅助标记也能正常确认。
- 本次只确认两图的对应关系；地点综合判断仍需合影双 S 等已有另一条证据。

### 7.4 提交、反馈和状态

- 固定一个“记录这处对应”主按钮。前置仅包括候选存在、依据已选；不包含 zoomLeft/zoomRight、选框或工具点击次数。
- 若缺选择，说明缺哪一类操作并将焦点带到相关控件，不自动选答案。
- 状态层验证当前是 T07、候选确实已截图且支持对应、依据有效。不得只在组件中判断成功，不要求可选选区作为证据前置。
- 成功在一次语义动作内写入 comparedFrameIds、`FLAG_A2_TEMPLE_FRAME_FOUND`、`NOTE_A2_T07_002`，触发对应事件且幂等。
- 现有 `confirmAct2T07TempleFrame` 可保留兼容用途，但新 UI 不再强制第二次调用。
- 失败不写成功状态，不丢候选和草稿，不弹“同一个东西”的肯定对话。给出与实际材料一致的反馈：只有环境相似、截图中看不清建筑、所选特征不能支持对应等；不判断玩家未必使用的选框。
- 小月的肯定台词移动到成功之后；核对前改成不带答案的邀请，例如“把之前拍的照片也打开看看”。
- 成功后在两图下方原位展开持久记录：两图来源/时间码、选中依据、一句暂定发现、“已记入调查笔记”。不能只改按钮颜色、仅显示底部吐司或再要求确认。回看已核对候选仍显示结果；缩放、切页不撤销证据。
- 合影线索尚缺时给出“查看合影中的标记”；两条证据齐全时给出“整理地点判断”。不自动进入下一幕。
- 外景对应、综合地点判断、出发各只确认一次，用“记录这处对应 → 整理地点线索 → 再次进山”表达，避免连续出现含义相近的“确认/继续/完成任务”。
- 完成记录后留在结果处，主操作顺势更新，照片/播放器不突然重置，让玩家看见刚才的操作改变了什么。

### 7.5 五个页签的调整

- “宣传资料 / 受访视频 / 外景对照”保留为工具页签，可自由切换。
- “地点结论 / 再次进山”不再伪装成与工具平级的调查步骤：改为成功后的摘要与主要行动区，保留回看入口。
- 综合判断未成立时不能提前展示确认后的对话、行程和结论；显示可理解的待核对状态即可。
- 保留旧入口 actionId 时通过路由映射进入新区域，避免桌面恢复入口或材料链接失效。

### 12.2 目标行为与实现约束

- 应显示的继续入口始终有清晰文案、背景、边界和焦点样式。收起菜单后的隐藏项不得遗留独立 fixed 点击层。

- 从根本上收敛 taskbar/浮层/场景的显示责任，不能靠不断抬高 z-index 或把所有透明元素全局禁点掩盖问题。

## 13. 工作包 F（P1）：1080P 调查版式、学校页面与按钮可读性

### 13.1 共用布局标准

- 首先在真实 CSS 视口 1920×1080、100% 页面缩放下验收，并补测物理 1080P 屏幕存在浏览器工具栏时的实际可用高度；记录尺寸，不把屏幕分辨率直接当成页面视口。
- 以 InvestigationShell 扣除顶部、导航与安全边距后的区域作为布局空间；宽屏主体使用约 90%–96% 可用宽度或等效合理布局，不再统一限宽 1120/1200px 后留巨大侧空。正文列保持约 32–48 个中文字符的舒适行长，利用多栏组织材料，不把一行正文拉满整个屏幕。
- 顶部呈现当前位置、当前目标、进度；中部为调查材料与操作；底部/侧栏为当前结果和下一步。宽屏首屏能看见当前调查对象、目标及至少一个有效操作。
- 不用 transform:scale、浏览器缩放、放大字号或把照片拉伸填满来假装修复空间利用。避免同时出现整页和三四个嵌套滚动区。
- 桌面可使用主区+侧栏；中屏根据内容折叠；手机改为单列和可展开材料，标签及主按钮不横向溢出。文字可滚动，必要操作不被固定栏遮挡。
- 行走方向使用“前往××/返回××”，调查对象使用“查看××”，提交使用“记录/整理××”；箭头只能辅助，不能作为唯一入口和含义。ready/blocked/completed 有可读文字及原因/反馈，不能只靠颜色区分。

### 13.2 老人调查（T02）

- 宽屏采用场景与对话/调查记录并列，建议约 55%/45%，随实际素材调整；场景保持比例，对话不用压在人物照片上。

- 已完成后的记录和下一步操作出现在当前内容附近，避免必须滚到长篇对白底部才知道调查完成。
- 不新增问话次数、不更改证据顺序；可选话题明确标记，完成要求来自现有状态动作。

### 13.3 图书馆（T03）

- 宽屏采用“目录/检索（约 220–280px）+阅读主区（弹性）+笔记/当前任务（约 280–340px）”；可按实际内容合并侧栏。阅读区应占主体，不能只扩张书架空装饰。
- 清楚显示当前书名、页码、翻页/返回目录；读到有效材料后显示“已记录”与具体线索摘要。需要比较的资料可从笔记直接回到来源页。

### 13.4 学校调查（T05）

- 叙述/长说明移到有独立底色的文字区域；确需叠图的短标签使用足够不透明的底板和边界，不能只靠文字阴影或整张照片调暗来提高对比。

## 16. 工作包 I（P0）：第三幕全体调查图片恢复原始比例

### 16.1 建立逐图清单并定位原因

1. 从第三幕场景数据和 `Act3Investigation` 枚举所有可达镜头及引用的图片，不只挑首张；对照图、复用照片、缺图 fallback 另列。每项记录阶段/镜头 ID、assetId/实际文件、naturalWidth/naturalHeight、当前图像与内容平面显示尺寸、父视口尺寸。
2. 在 1920×1080 记录初次进入、下一镜头、返回镜头、打开/关闭资料、缩放复位和 resize 的 DOM/截图。检查是否存在父容器强制定高、共享 img 选择器、flex 收缩、过期 imageSize/frameSize、未更新 ResizeObserver、加载前 fallback 比例造成的压扁。
3. 分别报告“图片实际被拉伸”“图像被裁切”“容器比例不匹配”“动画中的短暂错误”。源码风险与实测根因分开，交付至少说明哪条尺寸/生命周期链导致用户现象。

### 16.2 图像几何与生命周期要求

- 主调查图以原始资源尺寸为唯一比例依据。默认完整可见：`fit=min(viewportWidth/naturalWidth, viewportHeight/naturalHeight)`；内容平面为 `naturalWidth*fit × naturalHeight*fit`，使用同一缩放系数，不能分别拉伸宽高。
- 图片与图内热点属于同一内容平面，热点位置由原图归一化 x/y 映射；平移/缩放共同作用。导航、说明、缩放工具位于图外的固定操作层，不能随照片拉伸。
- CSS 做保持比例的防御，但不能只将 fill 改成 contain 后忽略热点坐标。若图片实际绘制区域小于平面，必须统一两者坐标，否则会出现“照片正常了、热点却错位”。禁止用 cover 裁掉证据冒充修复。
- 视口变化必须重新计算适配比例；ResizeObserver 观察当前真实 frame 节点，节点替换时重新绑定并清理旧观察。保留稳定 DOM 或正确绑定新节点均可，不能仅缓存首次尺寸。
- imageUrl/sceneKey 变化时，使旧图片的尺寸状态失效或以资源身份缓存并校验；onLoad 对应当前资源，快速切图不能让旧图回调覆盖新图尺寸。图片未加载时显示稳定加载态，不先按任意宽高拉扁，也不让旧图热点出现在新图上。
- 加载失败时显示可读错误/原有文字线索入口，不能只保留不可见图像上的热点；不允许用假尺寸或另一张图片替换证据。
- 缩放采用统一 scale，不使用 scaleX/scaleY 改变比例。平移边界基于缩放后的实际图像范围；缩小/窗口变动后重新限位，复位回到完整适配，不把图像甩出视口。
- 消除 flex 高度链与 min-height 造成的挤压。1920×1080 下给主图充足高度，同时容纳目标/导航；窄屏可重新排版和滚动，不强行把整张页面塞入一屏。
- 各素材比例可能不同，不统一写死 16:9、4:3 或相同高度。主场景因屏幕与照片比例不同出现适量中性外部余白是正常的；这与 T07 把 4:3 图塞进过宽定高卡片产生巨型内部灰带不同。不能为了零余白牺牲比例和证据。

- 第三幕破庙/空神龛对照取消一律固定 160px 高度加 cover 的证据展示策略；按各自自然比例展示，可设最大显示高度并提供查看原图，不裁掉判读区域。
