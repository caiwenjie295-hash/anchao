## 1. 产品决定与完成目标

第四幕定位为剧情回顾与揭示篇，主要任务是让玩家读懂小说里的经历、人物关系和前三幕留下的疑问。以小说原文及清楚的解释承载内容，图片作为配图。第三幕继续承担现场调查与悬念积累，但必须清除开发提示、改善人物行动的理由，并为第四幕的回收提供铺垫。

用户所说的“真实剧情”，本工单理解为小说中的正式故事与人物经历，不将虚构故事宣传为现实事件。解释应说明文本支持的联系，也保留小说没有确定回答的问题。

本轮必做：

1. 第四幕主线正文在页面直接可读，原文占主要位置；不再依赖点击照片热点才能看完整剧情。
2. 从完整小说逐段取材，为原文、改编衔接和剧情解释建立清晰边界及来源记录。
3. 组织好“调查者阅读资料 → 小 A 的经历 → 回到当下”的时间与视角切换。
4. 重写第三幕玩家可见的开发语气、图片生成说明、占位和流程管制文案；包含屏幕阅读器能读到的内容。
5. 补齐第三幕场景之间的行动理由、对话和关键线索的观察内容，让第四幕的揭示有前文承接。
6. 第四幕减少强制选择题、排序题和重复确认，保留一个有意义的账号密码互动及少量情绪性操作；阅读回顾不被答题卡住。
7. 设置按揭示进度开放的解释与前文回看；不让调查者提前拥有只在小 A 经历中出现的知识。
8. 保留有效存档、阶段完成状态、第三幕调查契约及上一份 UI 工单的成果，完成针对性测试与真实浏览器验收。

本工单允许第三、四幕相关叙述、第四幕谜题门槛、阅读状态和必要公共接口按下文修改；不授权改写小说结局、编造新证据、重做第一二幕或增加多结局。

### 7.1 切换视角与时间

- 回看目录只开放已揭示内容；同章未来片段也不得借解释链接提前访问。完结后开放完整第四幕与事件时间线，仍不把未确定的去向填成事实。

### 7.2 正文、解释和配图的页面结构

```text
章节标题：时间、视角、场景
当前段落的完整小说原文（默认展开，主阅读区）
可选配图（自然比例，无强制热点）
本段解释 / 前文回看（读到对应段落后出现）
上一段    继续下一段
已读章节目录 / 返回当前进度
```

- 1920×1080 可使用约 180–240px 目录、弹性阅读主区、约 280–340px 解释侧栏；原文是视觉主体，中文行长约32–46字，正文建议18–20px、行高1.75–1.95。空间用于正文和回看，不让大图挤占首屏。
- 中屏合并解释到正文下方，手机单列；原文直接可选中、复制、缩放和滚动。只有必要长内容可折叠，关键情绪/情节不能默认藏在弹窗。
- 每个完整场景通常按自然段分成约300–800字的阅读单元；短段保持短，高潮可更长，不为统一字数切断对话或反复点下一页。取材完成后记录实际字数与分段原因，不规定必须凑总字数。
- 生日、入所、身份异常、返山、最后逃离、尾声均须有完整情境与对话的原文节选；仅增加“查看更多原文”按钮而主线仍走旧短摘要不算完成。
- 图片可内嵌或靠侧，默认不超过当前阅读视口约25%–35%高度，按素材内容调整。图片可点开放大，关闭后回到正文位置；缺图时正文、解释和继续不受影响。
- 沿用上一工单的白/灰/深色文字主题；黑场只在必要转场和意识中断使用。底部操作不得遮正文/最后一行，长文优先使用一个主滚动区。
- 图片不承担精确解字、隐形按钮或必过线索任务；档案、日记、邮件中的关键文字用独立可读文本呈现。
- 图片 alt 简短描述画面；重复旁边正文且纯装饰的配图可 alt=""。artDirection/imageDescription 等制作字段不直接映射到无障碍名称。

### 8.1 推进与完成的语义

- “继续”表示玩家读完当前阅读单元并选择往后；不以滚动百分比、停留秒数、图片加载成功或展开解释来判断理解。

- 取消强制谜题必须同时改 UI、`laterFlow`、StateManager 和存档清洗；不得只删组件，底层仍等待旧 solvedPuzzleIds。
- 建议增加统一 narrative progression policy，列每章可访问的段落、必要自然动作和下一个段落；UI blocked reason 与状态拒绝使用同一策略，避免两套不同门槛。
- 旧 puzzle ID 保留作为历史存档信息，不自动把所有退休题加入 solvedPuzzleIds 装作玩家完成了答题。新门槛直接表达阅读/资料打开动作。
- T09 意识中断通过视听/文字承载；不破坏鼠标、键盘方向、浏览器响应，不伪装产品崩溃。减少动态效果/纯文字模式仍读到相同事件和“回收完成”。

## 10. 数据设计、接口与存档

### 10.1 建议结构

新增 `src/data/narrative/` 或同职责目录，分别存第三幕玩家文本、第四幕原文阅读单元、解释、来源映射和推进策略；避免把大段原文堆进 JSX。

建议类型（可按仓库调整）：

```ts
type NarrativeSection = {
  id: string;             // 稳定 ID，不用数组下标作为存档 ID
  stage: Act4Stage;
  title: string;
  perspective: 'investigator' | 'wangao';
  periodLabel: string;
  blocks: Array<{
    id: string;
    kind: 'novel-excerpt' | 'adaptation-bridge';
    paragraphs: string[];
    sourceRefId?: string;
  }>;
  illustrationAssetId?: string;
  illustrationAlt?: string;
  explanationIds: string[];
};
```

解释与 sourceRef 在独立映射中存放，含 unlock/reveal 条件、来源章节/页码/起止锚句；制作提示不从此对象自动透传到DOM。所有引用、next ID、资源 ID 和门槛由数据验证测试检查。

### 10.2 状态动作

- 可新增 `advanceAct4NarrativeSection`、`openAct4NarrativeMaterial` 或等效语义动作，校验当前阶段、当前阅读单元及合法必要动作；返回成功/已完成/不合法顺序/尚缺材料等结果。
- 保留 `startAct4` 的第三幕完成且已撤离前置；保留主动登录、档案打开、藏笔记、最终邮件等操作的可访问性和幂等。
- 阅读正文与展开解释不是证据自动写入；当下取得的笔记/邮件状态与玩家读到的亲历章节各自保存，不混写到当下记事本。
- 旧 `birthdayNodeId`、`laterNodeId`、seen IDs 可映射到新阅读单元；原有阶段 Flag 保留并在合法完成时写入，不通过伪造谜题全解来满足旧逻辑。
- 当前有效正文位置/已揭示单元必须可保存恢复。具体 scrollOffset 可以是临时阅读偏好，但刷新至少回到当前单元，不跳回第四幕第一段；回看位置和主线位置分开。

### 10.3 迁移要求

- 上一任务可能已从schema10升级；本任务新增持久字段时从实际版本升级到实际下一版本。默认值、类型、导入导出、清洗和迁移统一更新，不能偷偷重解释同版本字段。
