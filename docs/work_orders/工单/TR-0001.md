# TR-0001 转场时机与行动衔接

> 状态：权威执行工单
> 基线：`23934d1`
> 执行角色：Agent（GPT-6 Sol，低思考）
> 分支：`agent/TR-0001-transition-flow`
> 规则：执行角色可以读取但不得修改本工单

## 目标

让玩家在完成调查动作后自然进入下一个地点或应用，消除“先抵达目的地、再读出发说明”和“按钮说去某处却只关掉黑幕”的断点，并让第一幕末到第二幕开头成为一次连续过渡。

## 必须交付

- 第一幕 B 的“去翻旧邮件”确认后，邮箱应实际打开并获得焦点；其他指向具体应用或目的地的转场按钮也应与实际落点一致。若按钮只关闭文字页，使用中性动作文案。
- 第一幕 H、I、返程以及第二幕 T02–T05 的地点切换，不再在目的地可操作之后额外出现通用“下一步调查”卡。玩家从原有剧情入口主动出发，转场先呈现，确认后才可操作目的地。不要借转场按钮替代既有剧情门槛。
- 第一幕末点击进入第二幕后直接呈现第二幕开场，不发生“幕末黑屏 → 桌面提示卡 → 黑屏 → 桌面”的反复切换。
- 保持序幕、阶段 Flag、资源 ID、存档键及 schema 6 不变；转场阅读进度仍通过现有 `seenIds` 幂等持久化，重载后可正常继续。
- 为上述关键行为增加有意义的自动验证；最终提交到任务分支。

## 非目标

- 不开发第二幕 T07，不改剧情结论或调查门槛。
- 不制作新图片、音频或视频；不做全局窄屏布局重构。
- 不统一重写所有转场文案；只调整为匹配实际动作所必需的按钮文案。

## 冻结接口

| 接口 | 精确约定 |
| --- | --- |
| `data/story_transitions.json` 的转场 ID | 保持现有 ID、phase、trigger、requiredFlags；允许调整 actionLabel 或添加呈现/目标元数据，必须有类型校验 |
| `modules.storyTransitions.seenIds` | 保持现有存档结构，只记录已确认的转场 ID；不得用它推进剧情阶段 |
| `StateManager` | 剧情阶段与 Flag 仍由现有入口推进；转场确认必须幂等，不得绕过前置条件 |
| 场景/应用入口 | 保留现有主动出发按钮和正常返回桌面能力；转场按钮只完成对应的可见导航或揭示 |
| 减少动态效果 | 如增加淡入淡出，必须尊重 `prefers-reduced-motion` |

## 验收标准

- [ ] 玩家读到母亲消息后可继续浏览微信；选择转场并点击“去翻旧邮件”后，邮箱实际在前台。
- [ ] 从溪谷进山洞、山洞进破庙、破庙下山及 T01→T05 的地点切换不会先暴露可操作目的地再显示出发说明；没有重复的通用提示卡。
- [ ] 第一幕末进入第二幕只经历一次连贯的黑幕衔接，然后到第二幕桌面。
- [ ] 在待确认转场上重载可继续，已确认转场不重播；剧情阶段、Flag 与存档迁移保持原有行为。
- [ ] 键盘焦点可见，背景在模态转场期间不可操作；新增动画尊重减少动态效果。
