## 建议开发顺序与公共契约

1. **T00 建现场图像壳并接第二幕。**数据驱动定义画面 ID、前后视角、可操作区域、提示文字、退出/返回、相邻图预加载；视觉主要内容为本地图片，没有图片时可用明确的本地占位与可操作文字。以旧电缆的断点和排水沟的连续方向建立调查节奏；T00 末图与 T01 首图使用同一外门。
2. **T01 接外门与双层围栏。**复用 T00 的图像壳，标牌、旧宣传照对照与两层围栏为本 T 的新操作；不能再次播放“出发/抵达”过场。
3. **T02–T03 接地面空间。**沿同一条走廊推进，既有门、窗、消防栓位置须连续；不允许一张图里消防栓在左、下一张突然到右。第一幕和 T05 的消防栓只作为视觉记忆，不回改旧场景。
4. **T04–T06 接地下空间。**从楼梯到档案室、广播室、厨房的房间顺序固定。手电是视野表达，不做精确像素点击或会卡关的电池消耗；纸片上的异形标题和六个词由游戏文字层排版，不依赖图片模型生成准确文字。
5. **T07 沿来路返回。**回到一层时可复用前面镜头，新增较暗的回程角度及蹲下视角；玩家获得笔记后因天色已晚离开。幕末只展示首页 A.W/字迹和物证，不自动跳第四幕。
6. 每个 T 只写本 T 的新场景、数据、资源 ID 与所需的公共状态增量；`GamePhase` 规划为 `A3_T00`—`A3_T07`。存档 schema 在每次实际实施时按已合并基线决定，不在规划稿预设数字。Flag、事件和资源 ID 以各工单为准，必须经统一状态管理幂等写入。

## 每部分主审验收

- 对照小说画面顺序与人物行动；检查前后镜头空间连续，不出现换位置、突然增加/消失的物件。
- 从第二幕 T07 结尾经 T00 到当前 T 可以连续游玩，返回、重载、清零安全；先前 T 与第二幕不回归。
- 键盘、鼠标、触摸都能完成调查，焦点可见；关键线索不靠唯一像素命中。
- 1440×900、1024×768、390×844 实际浏览器检查；无图片时仍可操作、无破图和外部请求。
- `npm test`、`npm run build`、`npm run build:offline`、`npm run test:offline`、`git diff --check` 通过。主审出具 `APPROVED` 后才合并。
- 检查外部 Agent 的分层交付：改变热点样式、布局、过渡或图片时无需改剧情 Flag/存档；无图、有图及减少动态效果时语义操作一致。各阶段逐单审查；T07 后按公共契约做第三幕总验收。
