## 冻结数据结构与内容

`data/act2_bridge.json` 必须包含可追溯顶层记录、场景文案、证据列表、老人列表、谜题和完成反馈；`act2BridgeData.ts` 负责类型化、校验和只读查询。

1. 至少 4 位老人，ID 使用 `ELDER_A2_T02_001+`；只有一位 `isClueElder: true`。所有人都有生活性闲谈，整体覆盖山路、年轻人徒步、村里旧闻、邪祟说法、“吃什么补什么”，不得显示任务头标。
2. 证据只允许 `IMG_A1_I_001`、`IMG_A1_I_002`、`IMG_A1_I_003`；数据中写明中性名称和说明，UI 可复用 `EvidenceImage`。
3. 只有选中线索老人并向其展示至少一张允许证据后，调用 `showAct2Evidence()`，随后幂等写 `FLAG_A2_ELDER_PHOTO_SHOWN`、`FLAG_A2_HEIBUMU_AUDIO_HEARD`，并加入 `NOTE_A2_T02_001`。
4. 无正式音频时使用可访问的“重听口述”按钮与 `aria-live` 文本，标记 `data-audio-id="AUDIO_A2_T02_001"`；只显示原话“黑捕木”，系统不得自动替换成答案。
5. 三段选择固定为：首字 `黑/嘿`，中字 `捕/补/埔`，末字 `木/母/墓`；通过 `setHeibumuNameChoice()` 持久化并由 `confirmHeibumuName()` 判定。
6. 连续 3 次错误后只锁定中间字“补”，并显示来自 JSON 的弱提示；不得自动选择首字或末字，不得自动提交。
7. 解出名称后显示正式词条和老人补充，幂等写 `FLAG_A2_COUNTY_RECORD_HINT_KNOWN`，加入 `NOTE_A2_T02_002`。核心层会写 `FLAG_A2_HEIBUMU_NAME_SOLVED`，组件不得重复实现判定。
8. 完成后出现按钮“去县图书馆查地方志”；点击才调用 `setAct2Stage('library')`。未解出前不得推进。
9. 组件接受可选 `manager?: StateManager` 以便隔离测试；不得直接访问 localStorage 或修改状态对象。
10. 组件仅在桥头场景内使用原生按钮/单选语义、可见焦点、键盘可操作、明确返回桌面按钮或回调。减少动态效果时禁用非必要过渡。
11. CSS 使用独立 `.act2-bridge*` 作用域，营造县城桥头/休息区的克制占位场景；不使用远程资源、不伪造正式照片。

## 测试要求

- 数据测试覆盖 ID 唯一、恰好一个线索老人、三张证据白名单、对话非空、生活噪音覆盖、谜题选项和正确答案。
- 组件测试覆盖：普通老人展示证据不触发；线索老人触发口述；重复展示幂等；错误答案不完成；3 次错误只锁中字；正确答案写 Flag/笔记；完成前后阶段门槛；重载状态可继续。
- 测试不得依赖 WB-0002 分支已经存在的笔记正文，只验证冻结 ID 被写入状态。
