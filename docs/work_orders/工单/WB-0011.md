# WB-0011 离线包拆分与资源按需加载

> 状态：Codex 主审冻结，待外部执行 Agent 实施

## 目标

将当前约 73 MiB 的单文件离线入口拆成“启动入口 + JavaScript/CSS + 图片资源”的离线目录，降低首次打开时的内存峰值和更新成本，同时保留双击入口、桌面状态、存档、内置浏览器、窗口系统和离线剧情流程。

## 设计结论

- 交付结构采用相对路径资源，不依赖 Windows 文件系统软链接；软链接在换电脑、压缩包解压和权限不同的环境下不稳定。
- 内置网页搜索继续使用 React 组件和数据驱动的虚拟页面，不为每条搜索结果生成独立 HTML。页面之间的“链接”继续由应用内标签页、后退/前进和 `BrowserPageView` 管理。
- 默认离线输出目录为 `暗潮离线/`：入口 `index.html`，其余文件放在 `assets/`。具体文件名可由 Vite 生成，但入口必须能在 Windows 本地双击打开。
- 图片不得全部以内嵌 Base64 形式写入入口；构建应尽量使用相对资源 URL，并关闭或显著降低资源内联阈值。
- 如为了兼容 `file://` 需要保留 IIFE 或其他单脚本形式，允许将脚本保持为单文件，但图片和大资源必须外置；不能为了拆包引入网络请求。

## 必须保持

1. 双击 `暗潮离线/index.html` 可启动，不能要求用户先运行开发服务器。
2. 保持 `anchao.save.v1`、现有存档 schema、localStorage 行为、清零和重载行为。
3. 保持桌面六应用、窗口拖动/缩放/最小化/最大化、标签页、历史、后退/前进、第一幕 A–K 与第二幕 T01–T06 流程。
4. 所有本地图片、字体和脚本只能从输出目录加载；不得出现 `http://`、`https://` 或 CDN 请求。
5. 内置浏览器的虚拟新闻、论坛、百科等页面仍由现有数据和组件呈现，不改变剧情正文、Flag、资源 ID 或页面访问记录。
6. 缺失资源时必须有可理解的本地回退，不得出现破图后无法继续的状态。
