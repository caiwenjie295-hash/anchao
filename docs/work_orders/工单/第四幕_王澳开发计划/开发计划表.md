# 第四幕《王澳》开发计划表

> 状态：剧情与系统结构规划稿。十个阶段尚未冻结为执行工单；实际开发前须核对第三幕 T07 的合并实现、存档版本和文件所有权。
>
> 范围：从第三幕带离小 A 笔记后的县城夜晚，到数月后收到启明最后一封邮件。原文依据为《暗潮_0916_校订稿.pdf》第十五章末至第二十二章，四幕总纲只作为改编参考。
>
> 实施原则：不修改第一至三幕已经验收的步骤；复用照片、邮件、微博/浏览器、记事本、第三幕现场调查和存档能力。第四幕是完整剧情核心，不把十段压成一段自动播放的真相说明。

## 一、这一幕要回答什么

玩家先解决一个可验证的问题：**小 A 留下的账号如何打开？** 随后沿账号记录和亲历重构，逐层接近更难的问题：**他在启明经历了什么，为什么会有黄子山的记忆，2020 年为何再回去？** 高潮回答他最后一次行动的经过，却不替原文回答其最终下落、肉食的确定来源或黑补母机制的物理原理。

结构上有三条不同的信息线，不能混成一条“调查结果”：

| 线 | 玩家看到的载体 | 角色在当下真正掌握的内容 | 作用 |
| --- | --- | --- | --- |
| 当下调查 | 酒店桌面、纸笔记、旧邮件、微博、启明邮件、两张纸片 | 可保存、引用、比对的物证和推论 | 玩家主动推理，推动账号与词表问题 |
| 小 A 经历 | 2014 年生日、机构生活、记忆错位；2020 年回返 | 这是**给玩家体验的叙事视角**，不是主角与小月凭空取得的录像或证言 | 使事实有人的重量，让前几幕空间在不同时间复现 |
| 现实尾声 | 求证无果、三杯饮料、联系渐疏、启明邮件 | 现实中仍能确认和无法确认的边界 | 结束人物关系，留下制度仍可能存在的余波 |

**时间与揭示顺序：**第三幕当下 → 县城夜晚读笔记 → 2020 年账号记录 → 2014 年小 A 亲历 → 2020 年 4 月 19 日重返启明 → 当下与数月后。每次跨时间线显示日期和视角身份；从小 A 视角回到当下时，主角笔记只保留物证支持的结论。

## 二、谜题是第四幕的主要玩法

本幕规划 **24 个短谜题与互动：十个阶段各有一个必要的主线确认，另有十四个可选的理解与情感互动**。每题通常只需两三次明确操作，目标时长 30—90 秒；答案就在刚看过的原文线索里。没有限时、账号锁定、任意密码、隐藏像素或依赖听力的唯一答案。玩家做错时保留已完成步骤，并获得更具体的观察提示。

当下调查主要用排序、配对、比照；小 A 视角主要用观察、确认、空间回声；最后几步则让玩家亲手留下笔记。谜题会改变玩家获得线索的过程和细节，不改写 2014 年被送走、2020 年倒下等既定事件。每题的输入、答案、提示与必要性见 [谜题与互动设计](谜题与互动设计.md)。

## 四、玩家可执行的调查方向

1. **笔记的空间核对。**九页笔记依凌晨时刻排序，用第三幕去过的洞、排水沟、双层围栏、地下室和消防栓照片核对；乱码可帮助判断失控程度，但不做要求逐字还原的文字谜题。
2. **旧邮件日期与密码。**两个账号、同密提示、2020 年 4 月 19 日 23:41 的旧邮件共同构成答案。允许玩家自行输入，也提供基于已看证据的推理提示；错误输入不锁号、不惩罚存档。账号地址以原稿核对后登记，必要时按现有邮件/浏览器模块的数据结构呈现。
3. **微博时间线的变化。**用日期和生活细节让玩家观察“口味、社交、情感、记忆”四组变化；结论由玩家主动确认。4 月 3 日收到启明邮件与开始记录微博的顺序须正确。
4. **两组广播词的比对。**第三幕拿到的 `VVaKe`、`13aCK` 两纸和 2020 年邮件、2014 年广播互为参照。词语及顺序由文本层精确呈现，实际含义在尾声才由小月提出 `wake/back` 的读法；不把这组词做成随意排列的密码锁。
5. **同一地点跨年对照。**2014 在用机构、2020 运营中的机构、当下废墟使用相同门柱、走廊、档案馆、广播室、厨房、消防栓的空间锚点；玩家能认出物件的年代变化，不让回忆段凭空出现新建筑结构。
6. **身份错位的证据链。**学霸笔记双 S、黄子山成功案例、黄子山档案、2014 年小 A 的梦、2020 年的误认彼此照应；玩家可得“记忆/人格似乎被混入”的推论，不能在没有新原文证据时宣布具体技术、公式或灵异法则。
7. **最后的回声。**消防栓、主角回复邮件、笔记包裹及出口门槛复用第三幕已有地理关系。此段玩家参与写与藏、尝试前进，却无法通过更快操作改写原文结果；游戏应明确这是重构既定往事。

## 五、关键转场与视角规则

- **第三幕 → T01：**第三幕只在离开旧址后结束；第四幕用县城回程的短过渡、烧烤店的沉默和酒店桌上的笔记承接，不重放第三幕收束黑幕，也不突然切成完整桌面首页。
- **T02 → T03：**密码确认后保留当下酒店视角，账号界面作为调查工具打开；微博日期连读需要可返回笔记和旧邮件，不让播放器吞掉证据。
- **T04 → T05：**当下证据到此为止；以明确的“2014 / 王澳（小 A）”时间与视角标记进入玩家专属亲历段。这一段可提供暂停和回看，不把私密对话自动写入主角证据簿。
- **T07 → T08：**2014 高中窗边/双 S 与 2020 年湖边清醒形成视觉回环；日期跳到 2020-04-03，再到 04-19。小 A 返山不是主角再次进山。
- **T09 → T10：**“回收完成”后黑场短暂停顿，回到现实调查；不紧跟解释字幕。尾声三杯与最后邮件之间显示数月流逝，并保留邮件原有冷淡措辞。

## 六、开发分层与资源方向

- **技术边界：**继续用 React + TypeScript + Vite。场景/账号数据、剧情与存档、输入动作、表现组件和局部 CSS 分离，沿用第三幕[公共开发契约](../第三幕_启明遗址开发计划/公共开发契约与执行提示词.md)的原则，但第四幕须按每份新冻结工单确定路径与接口。微博、邮箱优先扩展已有模块；小 A 回忆可复用现场图像壳的镜头/热点能力，不复制一套平行状态系统。
- **谜题实现：**每题用稳定题目 ID、证据 ID、语义动作、正确条件、提示层级和完成回执登记在阶段数据中；状态管理只保存首次完成及必要线索，不保存纯拖拽坐标。排序、配对、观察可共用轻量交互组件，但不要为了 24 题新建难维护的通用解谜框架。谜题逻辑可独立测试，换图片、换按钮或改布局时不改答案和存档。
- **状态边界：**先对照已合并的 `FLAG_A3_COMPLETE` 等实际入口契约，再规划 `A4_T01`—`A4_T10`。关键状态保存“已阅笔记页、已核对日期、已登录账号、已标注时间线、已完成证据对照、已看过重构段、尾声进度”等语义节点。播放时间、光效和视觉失焦不进核心进度。Flag 与存档 schema 数字只在各阶段开工前冻结，不在规划稿硬定。
- **图片方向：**当下酒店与屏幕调查可复用现有 UI 和证据图片；2014/2020 第一人称段延续低饱和、手机拍摄、极度写实。回忆失真主要通过局部曝光、声音和文字层处理，不能让画面风格变成另一款超现实游戏。所有图片按 `IMG_A4_TXX_YYY` 预留稳定 ID；逐阶段冻结准确数量和生成描述，旧址跨年母图须先用第三幕获批图做参考。此计划不生成图片或登记不存在的资源。
- **高潮交互：**逐词广播以叙事状态推进，允许鼠标、键盘、触摸同一语义操作；可用失焦、延迟的*视觉反馈*表达失控，不真正随机吞输入、反转方向或让玩家无法退出。减少动态效果、静音和无正式音频路径应保留完整字幕与可推进流程。
- **阶段交付：**每 T 单独冻结工单、分支、worktree、唯一写入者与允许路径；先验收再合并，再冻结下一 T。外部 Agent 不能自行修改第一至三幕或合并 `main`。总验收由 Codex `gpt-6-sol` `high` 从第三幕终点走到最终邮件，提出可定位到阶段、镜头和组件的修改意见。

## 七、总验收标准

- 剧情顺序与日期一致；2014、2020、当下视角随时可辨，主角的推论不引用只有玩家看到的私密回忆。
- 九页笔记与账号密码链能独立走通；错误密码、缺图、重载、回看和清零均不会越级授予进度。
- 十个主线谜题均可用鼠标、键盘和触摸完成；可选互动能跳过而不阻断结局。每题有明确反馈与递进提示，且不要求精确点击、隐藏倒计时或试出随机答案。
- 微博、邮箱、两纸词组和广播原词一致，`VVaKe` 与 `13aCK` 的联系按原文节奏揭示。
- 2014 的机构及 2020 的返校与第三幕废墟对位；现有第一至三幕流程、资源和存档没有回归。
- 小 A 的最终去向、肉食来源与机制不被游戏伪造成已证实事实；“左脚出门—倒下—回收完成”与尾声邮件保留原文张力。
- 无图/有图、静音/有音、减少动态效果、宽屏/窄屏均能完成。每阶段运行 `npm test`、`npm run build`、`npm run build:offline`、`npm run test:offline`、`git diff --check`，并做真实浏览器检查。最终由主审审查报告和实际游玩后决定合并或退回修改。
