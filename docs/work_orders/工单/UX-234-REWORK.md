- 玩家清楚知道自己在哪里、正在调查什么、哪些操作可以做。

## 3. 固定的设计与剧情边界

### 3.1 三幕各自回答的问题

| 幕 | 玩家核心问题 | 幕末获得 | 不得提前坐实 |
| --- | --- | --- | --- |
| 第二幕 | 山中记号、民俗与小 A 的变化有什么关联？ | 小 A 与启明的关联，以及启明旧址的地点线索 | 机构机制、身份转移原理、小 A 的结局 |
| 第三幕 | 启明如何运作，小 A 是否重新来过？ | 机构环境、两组词表、民俗关联迹象、小 A 藏下的笔记 | 黄子山档案全文、肉的来源、小 A 的最终去向 |
| 第四幕 | 笔记和账号能还原怎样的经历？ | 密码回收、生活时间线、身份冲突、藏笔记与失控的经历 | 当下调查者无来源地掌握小 A 私人记忆；把推测说成机构定论 |

- 保留姓名、日期、账号、词表、关键资源 ID 与结局事实。地点称谓如鸡公岭/鸡头岭先核对现有规范，记录映射，避免全局替换小说或制造新地点。
- 第三幕当前厨房内容为“空神龛与底座”；不要按早期方向稿改成当下仍摆着完整黑像。
- 第四幕亲历内容属于小 A 的过去，不能自动进入当下主角的证据簿。
- VVaKe / 13aCK 与 wake / back 的关联仍按当前内容保留为人物联想。
- 改进按钮文案、任务提示、短衔接和证据提问属于本任务；增加人物经历、改因果、改死亡结论不属于本任务。

### 3.2 通用调查循环

每个关键节点按以下链路设计：

`当前疑问 → 可接触材料 → 玩家观察/比对 → 有证据支持的判断 → 具体行动 → 新疑问`

材料允许提前读，问题允许暂时放下。阅读本身不能自动代替重要判断；环境细节也不能全部变成强制答题。

## 4. 共用 UI 与导航合同（P0，先完成）

### 4.1 布局

```text
顶部：第二/三/四幕 · 当前地点 · 时间/视角        菜单/返回桌面
简短目标：当前正在查清的问题                  求助
┌─────────────────────────────────────────────────┐
│ 场景照片 / 材料阅读区                              │
│ 物件热点属于图片；画面缩放不影响外部导航             │
└─────────────────────────────────────────────────┘
固定操作区：返回上一处 | 可前往地点/主要行动 | 调查笔记
状态区：操作结果 / 当前受阻原因 / 查看相关材料
```

- 照片容器只负责观察。导航区放在 transform 层外，不能随照片 zoom/pan 改变可见性。
- 场景照片可保留门口快捷入口，但必须与固定导航使用同一个动作定义和判定。
- 当前地点和视角常显；禁止把内部 T 编号、Flag 或资源 ID 暴露为玩家任务。
- 宽屏优先完整呈现照片，窄屏将多个去向收进常显的“可前往地点”展开控件，不压成图标谜题。
- 固定操作区不能遮挡正文末尾、字幕、热点或系统安全区域；横屏低高度允许内容区域滚动。

### 4.2 操作语义

| 类型 | 表现与文案 | 行为 |
| --- | --- | --- |
| 观察 | 物件热点，例如“查看门牌” | 进入特写，不推进故事时间 |
| 空间移动 | 常显目的地，例如“前往广播室” | 进入相邻且允许访问的位置 |
| 返回 | “返回走廊/返回现场” | 返回实际上一层，不撤销证据 |
| 剧情行动 | “收好笔记，回酒店” | 明确地推进阶段或时间 |
| 回忆切换 | “回想睡前的广播”并注明时间/视角 | 不伪装成同一空间的方向箭头 |
| 回看 | “回看中”+“返回当前进度” | 只读展示，不增加进度 |

- 箭头只是空间移动的辅助图形；不能仅显示无文字箭头。
- 不用数组索引推断前进/返回，路线数据明确记录目标和动作类型。
- 一个按钮在当前显示状态下只表达一种结果；回看页面隐藏当前剧情的推进按钮。
- 退出调查到桌面、关闭特写、回到上一处是三种不同动作，文案必须区分。

### 4.3 受阻反馈

- 区分 unavailable（该动作不存在/尚未发现）、blocked（已知入口有前置）、ready、completed。
- 尚未发现的房间和未来剧情不提前列出；已知但受阻的入口必须能够获得解释。
- blocked 入口保持可聚焦，可通过“查看原因”或点击入口得到就近、常显的原因，不能只有不可点击的 disabled 图标。
- 显示原因时不自动打开包含全部题目的长弹窗；给出“查看相关材料”的明确按钮。
- 反馈提示证据缺口，不直接给出正确选项。例如“还没有核对这两张照片”，而不是“请选择第三张照片”。
- 无关环境热点没看，不阻止离开；具有剧情理由的门槛仍必须由状态层执行。
- 避免“缺少线索 → 要到下一处找 → 下一处又被这条线索锁住”的循环依赖。

### 4.4 热点、缩放与弹窗

- 物件热点随图片移动，但导航、复位、关闭按钮不随动；调查热点最低有效点击区域建议 44×44 CSS px。
- 热点坐标必须对齐实际图像。当前图片使用 object-fit: cover，需处理容器宽高比变化造成的裁切；可采用可预测的等比完整呈现，或根据真实图片变换计算坐标，不允许只把百分比坐标原样贴在任意裁切容器上。
- 同一地点开关特写后恢复缩放与位置；更换地点可复位。按需“显示可调查区域”不展示线索答案。
- 标记“已查看”不等于“已解决相关疑问”；两者状态不混用。
- 模态弹窗限制焦点在内部，打开后合理聚焦，Esc 可关闭，关闭后恢复原触发入口；没有悬停能力也能完成所有操作。
- 图片缺失时保留文字观察和导航入口。辅助模式、reduced motion、字幕路径仍可通关。

### 4.5 建议实现职责

可新增 `src/components/investigation/`、`src/data/investigation/` 和 `src/story/investigation/`，具体组件名可微调，职责不得混淆：

- `InvestigationShell`：统一布局、地点、视角、操作区。
- `InvestigationNavigation`：显示路线与行动，不写剧情 Flag。
- `InvestigationDetail`：特写和材料，负责焦点与关闭。
- 导航定义包含稳定 actionId、kind、target、label；不依赖照片坐标来保证唯一通路。
- 共用纯判定函数返回 allowed/原因/关联材料 ID；界面和 StateManager 使用相同的前置判定，避免 UI 显示可走而状态层拒绝。
- 区分“确认判断”和“进入下一阶段”的动作。确认后先给反馈，离开由明确动作触发；完成状态不能导致重复弹窗或自动连跳多幕。

## 5. 第二幕整体优化

### 5.1 网络调查转向当地调查（T01）

- 保留网络信息不足的叙事，但移除“必须恰好搜索完两类固定词句”作为唯一出发条件。
- 玩家查看一次相关搜索结果后，可从已知地方、照片、人物联系方式提出线下求证；给出“向当地人打听”行动。
- 对“补”和“双 S”的两条搜索保留为可选调查；已有搜索 Flag 仍记录真实行为，不在后台伪造搜索完成。
- 搜索做确定性的关键词归一化：空格、大小写、常见别名、同一组关键词顺序变化。精确匹配优先，模糊结果限制在当前已解锁材料。
- 搜索失败给出可理解反馈和既有关键词，不让空结果等同于系统坏了，不提前推荐未来人物或机构。
- 缩减等待计时器主动催促；主要由玩家求助或重复无效操作触发提示入口。

### 5.2 桥头对话（T02）

- 明确“选择交谈对象—出示证据—询问问题”的顺序与状态。
- 相关人物即可提供主线信息，其他人的内容为补充，不要求全部对话穷举。
- 保留名称辨认，但保证文字材料足够支持判断，无音频也能解。
- 得到地方志线索后，在固定操作区显示“去县图书馆”，返回桌面后可以直接继续。

### 5.3 图书馆与志异（T03–T04）

- 导航分三层：阅览室/目录、卷册、书页；提供明确面包屑或返回当前卷册。
- 找到书页后自动登记该材料来源，摘录只用于玩家主动选择的证据，删除无意义的重复确认。
- 三篇志异保留原文与白话辅助。白话译文不能直接代替跨篇推论。
- 将 12 卡“人物/缺失/进食/异变”分类改为紧凑对照表加核心判断：获得了什么、同时出现什么、是否足以断定来源。
- 玩家从至少两篇材料中选出支持性片段，再在有限的合理假设中形成“获得之外伴随陌生习惯/记忆”的暂时结论。第三篇用于补充验证；三篇正文始终可读，不要求每页盖章。
- 错误反馈指出假设与证据的冲突，允许保留已选正确材料，不自动填满正确答案。
- 不把“食用何物就转移某人的人格”写成第二幕已确证机制。

### 5.4 高中调查与机构调查（T05–T06）

- 学校采用统一地点导航，删除重复主导航。照片上的地点入口只作为快捷方式。
- 使用小月回忆、老师叙述、成绩记录，建立休学前后变化的简短时间线。
- 至少通过两个来源支持核心判断；选择的是证据含义，不是按页面访问数量自动生成结论。
- 双 S 对照保留图片并排与局部放大，让玩家指出共同特征，避免只点“确认相同”。
- 启明宣传、论坛和个案材料允许当前阶段内自由查看；同名判断必须有时间/经历等已有辅助信息，不凭姓名相同直接断言。
- 小月提供与小 A 有关的回忆和问题；她不是始终直接给答案的任务提示器。
- 本轮允许已发现资料跨模块回看；主阶段仍按现有顺序推进，不为实现两条线而引入复杂的全局并行剧情状态机。

### 5.5 宣传视频与地点判断（T07）

- 视频支持播放、暂停、拖动、逐帧与截取候选画面。截图动作不只在正确帧亮起，否则等于提示答案。
- 候选画面可与第一幕照片并排核对；正确判断需要选择已有画面及其对应特征。
- 可使用有限数量的本地候选帧 ID，不把大幅截图 base64 写入存档；错误候选可删除或替换。
- 移除播放覆盖率作为通关硬条件。历史“已播放”记录保留其原义，不自动伪造。
- 将“材料”“视频”“对照”作为工具，而不是必须逐项完成的步骤；去向操作放在固定区。
- 地点结论只在证据支持后可形成，再主动选择再次进山，最后进入第三幕。

### 5.6 第二幕验收

- 合理搜索表达不会因未命中唯一词句而卡死。
- 不读无关杂记、不问所有老人仍可推进；必要证据未取得时不能直接完成结论。
- 志异核心判断有至少一个合理但不充分的备选解释，失败有证据反馈。
- 学校返回、材料回看、切换桌面均保留有效进度。
- 不播放完整视频也能通过充分证据确认地点；截错帧不会损坏状态。
- 第二幕主线可连续走至第三幕入口，已经完成的旧存档可继续。

## 6. 第三幕整体优化

### 6.1 从“逐镜头清单”改为“有目的的空间调查”

- 保留 T00–T07 剧情边界和主路径，先在各阶段内部允许合理往返和不同观察顺序。
- 建立明确的房间/镜头/特写层级，返回特写不会把玩家送回桌面。
- 每个阶段定义必需证据与补充观察，新增独立的 requiredClueIds 或同等显式配置，不再直接把 `act3StageClueIds` 的全部结果当作必需项。
- 对每个必需证据写一句设计理由：它支持哪个判断，为什么不可缺。走到一层、听完重复描述等导航记录默认不算必需推理证据。
- 地图只显示已发现位置和已知连接。当前幕的有效探索可往返；跨已完成阶段回看使用只读模式，不能把主线 stage 改回过去。
- 检查阶段内所有必需证据从入口可达，且取得后存在前往出口的路径。

- 提供观察高度/角度的明确操作，玩家选择低处后才可见胶带痕迹。
- 若此前未主动读回忆，现场仍有合理获取回忆的途径，不能制造永久漏收卡死。
- 提示分为回忆相关人物、考虑观察高度、明确位置三层，最后一层仅主动请求时给出。
- 取出笔记和确认扉页后可撤离；不要求穷举所有回程镜头热点。

### 6.4 状态调整

- 拆开结论确认与离开阶段；完成结论不能自动将玩家从尚未关闭的材料弹窗传送走。
- 现有完成 Flag 与门槛 Flag 的写入时机逐个审核：事实在获得时写入，离开记录在实际离开时写入。
- 已完成阶段不重复奖励证据，不重复触发黑幕。
- 不通过给所有漏看热点写入 inspected 状态来“修复”新门槛。

### 6.5 第三幕验收

- 每个阶段至少验证一个“漏看非必要热点仍通过”的路径。
- 缺少必需证据时有具体原因且能返回取得，补齐后原入口立即更新。
- 地图和按钮不暴露未发现房间或未来线索名称。
- 从任一特写关闭后返回正确现场；放大到最大并平移到边缘后仍能移动。
- T00–T07 连续通关，包括取笔记、撤离、第四幕入口。

### 7.3 前半幕具体要求

- 笔记九页均可回看，关键推理需要相关页证据，不强制为了盖章逐页点完全部九页。
- 密码题保留“不要担心那一天”的回收。登录界面不提前说“共同日期就是密码”；求助逐层指向旧邮件与日期。
- 正确密码在账号入口可合法提交，不因玩家没做额外的确认题而被拒绝。账号与末页的发现仍需成立。
- 明确每条推理是集合匹配、字段对应还是时间排序，只有真正的时序题才要求顺序。避免所有谜题统一使用字符串 join 比较顺序。
- 打开邮件/帖子的顺序不影响结果，先看答案相关材料也不会软锁。
- 不增加原剧情没有的证据来强行证明超自然解释。

### 7.4 后半幕与高潮

- 热点只展示所点物件的内容；广播题只出现在广播对照处，档案查找只出现在档案处。
- 藏笔记动作完成后，立即获得“已经藏好”的结果与走向出口入口，不再反复确认。
- 广播采用连续场景序列：玩家主动开始尝试离开后，词语按既定次序出现，可暂停，字幕始终可读。
- 用场景明暗、角色行进表现和声音制造逐渐失控；不故意延迟鼠标输入、不反转系统操作、不让菜单失灵。
- 广播结束的事实顺序、门槛事件和“回收完成”保留；不改成玩家靠反应速度才能获胜或失败的 QTE。
- 无音频、减少动态模式仍能完整体验；快速显示/跳过已看演出必须通过同一合法完成逻辑，不越过前置条件。
- 暂停、退出、刷新后从已保存的词序检查点恢复，不重复启动多个计时器，不跳过最后一封邮件。
- 尾声保留三杯饮料、时间流逝和主动打开最后邮件，给予停顿，不追加材料清点。

### 7.5 第四幕验收

- 正确密码无需先在独立题中提交；错误密码不破坏已读资料。
- 可以先读微博再整理时间线，材料顺序可变。
- 已完成藏笔记动作后不再要求重复排序。
- 任意回看操作不改变阶段、已读事实和广播索引。
- 每个关键受阻点可以看见原因与相关材料入口。
- 完整走至 T10，最终邮件由玩家打开，完成事件只发生一次。

## 8. 调查笔记、提示与叙事节奏

### 8.1 笔记

基于现有 Notepad 升级，保留用户自由输入内容，不另造复杂案件白板。

- 提供“已有材料、当前疑问、已支持的判断”三类内容。
- 每条材料有来源与回看入口；照片/邮件/文献可并排对照。
- 获取事实时自动记录简短索引，不自动替玩家生成关键结论。
- 读过材料无需重复点“记录”才能使用；主动摘录用于推理选择。
- 当前人物无从得知的回忆放在独立回看区，不进入当下证据集合。

### 8.2 提示

- 一级：当前问题是什么。
- 二级：哪些已知材料值得对照。
- 三级：具体解题动作或方向，仅主动请求后显示。
- 提示根据当前真实状态生成，已完成问题不再催促；不能让提示自动完成题目。
- 不以普通阅读耗时认定卡关；反复无效操作可显示“需要帮助？”入口，不自动弹答案。
- UI 帮助与谜题提示分开：前者解释怎么操作，后者才涉及证据推理。

### 8.3 转场与节奏

- 大幅时间、地点、视角变化才用完整转场；相邻空间移动用短反馈。
- 减少“材料正文说一遍—笔记说一遍—黑幕再说一遍”的重复。
- 对每次离开说明具体行动动机，黑幕不代替关键推理。
- 解谜后的情绪段不强行塞入确认题。声音和字幕可在现有资源条件下完成，不阻塞于全套新配音。

## 9. 状态、存档和接口改造约束

### 9.1 状态一致性

- StateManager 或其明确委托的领域逻辑仍是持久化剧情的唯一写入入口。
- 导航判断、谜题前置、阶段推进共用可测试的纯函数；禁止 UI 与状态层各写一份条件。
- 查看、获取证据、形成判断、离开阶段分开建模，连点和重入必须幂等。
- UI 临时状态如弹窗开关、悬停、镜头缩放不需要全部进入剧情存档；关键调查草稿、已得证据、演出检查点应可恢复。
- 不新增全局“跳过门槛”开关；测试夹具只能用于测试，不进入玩家界面。

### 9.2 明确授权的变更范围

本工单允许为二三四幕的新推进规则新增必要的字段、语义动作与 Flag，并修改相应门槛；不再受旧工单“本阶段不得改动门槛”的局部实现限制。必须同步类型、默认值、清洗、迁移、数据定义和测试。

- 优先保持现有主阶段名称、资源 ID、存档键 `anchao.save.v1`。
- 如果持久化结构或含义发生变化，从实际当前版本递增；若接手仍为 9，新版使用 10。同步事件类型中的版本字面量。
- 旧题 ID、旧 visited/inspected 记录可保留为兼容来源，但不再强迫新玩家完成已删除的答题动作。
- 新的可选观察不得回写成旧存档中的已完成必需证据。

### 9.3 迁移规则

| 旧存档情况 | 新版本处理 |
| --- | --- |
| 已完成某幕 | 保留完成状态和下一幕入口，不要求重做新谜题 |
| 第三幕阶段内已看部分热点 | 保留真实看过的热点，按新必需证据判定，入口可达 |
| 第三幕确认与推进原本绑定 | 依据已有阶段/完成 Flag 映射到合法位置，不退回已结束阶段 |
| P04 已解但账号未登录 | 保留推导成果，仍提供账号登录入口 |
| 第四幕 P21 未答，但 packageStep 已为 3 | 直接映射“藏好笔记”的真实事实，无需再排序 |
| 旧 P23 未答 | 不再用该答题阻挡尾声，但保留对话与暂定解释 |
| 部分广播词已出现 | 保留索引与阶段，等待玩家恢复演出，不自动多播 |
| 缺失/异常新增字段 | 安全默认值；不得因此清空整份旧存档 |

迁移必须可重复加载，不能每次刷新推进一段故事。保留原先对 schema 1–9 的支持；用代表性夹具验证早期版本和 schema 9 关键断点。

## 12. 如何运行与证明测试

### 12.1 分阶段自动测试

先针对本阶段修改的领域与组件测试，再在关键集成节点跑全量。针对性文件存在后可按实际新增文件名运行，例如：

```powershell
npx vitest run src/components/investigation src/scenes/act3/Act3Investigation.test.tsx
npx vitest run src/scenes/act2 src/data/browserData.test.ts src/story/act2T01Controller.test.ts
npx vitest run src/core/act4.test.ts src/scenes/act4 src/story/act4
npx vitest run src/core/saveManager.test.ts src/core/stateManager.test.ts
```

这些是运行方式示例，不代表测试已创建或已通过。根据实际文件校正命令，不忽略“没有找到测试”的结果。

### 12.2 最终门禁

在任务 worktree 的仓库根目录执行并记录结果：

```powershell
git diff --check
npm test
npm run build
npm run build:offline
npm run test:offline
npm run test:browser
```

若新增了调查浏览器测试脚本，添加例如 `npm run test:investigation` 并运行。浏览器脚本必须采用隔离测试 profile/测试存档，不清除玩家正在使用的真实浏览器存档。

当前 `test:browser` 仅能证明离线入口基础挂载，必须增加或补充第 11 节真实交互验证；jsdom 不计算真实布局，不能证明箭头在视口内。

### 12.3 真实浏览器验证

- 尺寸至少覆盖 1440×900、1024×768、768×1024、390×844；至少一次窄屏触控语义验证。
- 第二幕选学校/图书馆/视频，第三幕选多路线场景/消防栓，第四幕选调查页/回忆页/广播结尾，覆盖全部界面类型。
- 关键导航使用实际点击/键盘操作；自动化时检查可见性、可命中性和操作后目的地，不只断言 DOM 存在。
- HTTP 开发入口完成二至四幕连续路径。离线入口验证三幕典型调查、一次跨幕和保存后重载，确认图片、脚本等无远程依赖问题。
- 最终离线入口以构建脚本实际输出为准；当前浏览器脚本读取 `暗潮离线/index.html`，不要只照旧文档打开一个过期的单文件 HTML。
- 截图至少包括：正常导航、3×缩放导航仍可见、受阻说明、窄屏、第三幕发现笔记、第四幕回看状态、广播暂停和最后邮件。
- 优先使用现有浏览器工具/本机浏览器。若自动化工具不足，可人工逐项操作并记录实际结果；不能以工具缺少为由标记浏览器验收通过。

### 12.4 报告要求

在 `docs/ux234/test-matrix.md` 为每个测试 ID 写：PASS / FAIL / NOT RUN、命令或操作步骤、证据文件、发现的问题与修复提交。

自动测试夹具可直接构造阶段起点，但从该起点后的被测行为必须走真实受控动作。至少保留一条连续跨幕路径，不能所有场景都靠修改存档跳转来代替。

若环境阻止某项验证：如实记录 NOT RUN 和具体原因，继续完成能做的工作；不得宣称已全面验收。真人盲测需要用户或外部测试者，不由开发者虚构完成。
