- 本幕**不做**第二次进山路上的电缆、排水沟、红砖追踪。这些是原文中的抵达旧址过程；如需可玩调查，应另在第三幕入口之前安排，不能挤进本计划的七个 T。T01 从锈蚀铁门、被爬山虎遮住的标牌前开始。
- 本幕**不完整阅读**笔记、不破解 `20200419`、不登录微博/邮箱、不解释 `VVaKe` / `13aCK`、不确认肉的来源，也不表现小 A 的最终命运。以上属于第四幕。

- 玩家可见地名沿用已发布游戏的“鸡公岭”；小说原文的“鸡头岭”不在本批工单中全局改名。小月与主角始终同行，不设计强制分头探索。
- 七个 T 串行执行、串行验收；一个执行 Agent 独占当前 T 分支和 worktree，不能同时写共享状态、图片登记或场景壳。每一 T 验收后才给下一 T 冻结基线。
- 当前七份 `工单.md` 是分阶段的规划稿。实际开工前，主审将对应工单登记为 `docs/work_orders/A3-TXX.md`，核对 T07 已合并后的真实文件所有权与存档版本，再交执行 Agent；不得拿尚未冻结的工单并行改共享文件。

## 建议开发顺序与公共契约

1. **T01 建现场图像壳。**数据驱动定义画面 ID、前后视角、可操作区域、提示文字、退出/返回、相邻图预加载；视觉主要内容为本地图片，没有图片时可用明确的本地占位与可操作文字。不因缺图阻断流程。
2. **T02–T03 接地面空间。**沿同一条走廊推进，既有门、窗、消防栓位置须连续；不允许一张图里消防栓在左、下一张突然到右。第一幕和 T05 的消防栓只作为视觉记忆，不回改旧场景。
3. **T04–T06 接地下空间。**从楼梯到档案室、广播室、厨房的房间顺序固定。手电是视野表达，不做精确像素点击或会卡关的电池消耗；纸片上的异形标题和六个词由游戏文字层排版，不依赖图片模型生成准确文字。
4. **T07 沿来路返回。**回到一层时可复用前面镜头，新增较暗的回程角度及蹲下视角；玩家获得笔记后因天色已晚离开。幕末只展示首页 A.W/字迹和物证，不自动跳第四幕。
5. 每个 T 只写本 T 的新场景、数据、资源 ID 与所需的公共状态增量；`GamePhase` 规划为 `A3_T01`—`A3_T07`。存档 schema 在每次实际实施时按已合并基线决定，不在规划稿预设数字。Flag、事件和资源 ID 以各工单为准，必须经统一状态管理幂等写入。

## 每部分主审验收

- 对照小说画面顺序与人物行动；检查前后镜头空间连续，不出现换位置、突然增加/消失的物件。
- 从 T01 入口到当前 T 可以连续游玩，返回、重载、清零安全；先前 T 与第二幕不回归。
- 键盘、鼠标、触摸都能完成调查，焦点可见；关键线索不靠唯一像素命中。
- 1440×900、1024×768、390×844 实际浏览器检查；无图片时仍可操作、无破图和外部请求。
- `npm test`、`npm run build`、`npm run build:offline`、`npm run test:offline`、`git diff --check` 通过。主审出具 `APPROVED` 后才合并。
