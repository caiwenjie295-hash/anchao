# 第三幕公共开发契约与外部 Agent 执行提示词

> 适用：A3-T00—A3-T07。每阶段冻结的 `docs/work_orders/A3-TXX.md` 决定具体剧情、允许路径、ID 和验收命令；本契约规定各阶段共同的前端与逻辑边界。
>
> 目标：剧情和存档正确、可连续游玩；画面布局、交互呈现及图片接入可以在后续主审意见下局部调整，不必重写剧情状态。

## 现有技术与四层边界

沿用仓库的 **React + TypeScript + Vite + CSS**、现有 `StateManager`、资源加载与离线构建。不要另建应用壳、另起路由或引入新的前端框架、UI 组件库、全局状态库、动画库与在线服务。确需新依赖或越出单份工单允许路径时，先提交最小变更请求，由主审修订工单后实施。

| 层 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| 场景数据与资源映射 | 镜头 ID、相邻镜头、可见线索、文案、图片 ID、动作 ID 和前置条件；从 JSON/数据模块读取并校验 | 颜色、排版、按钮尺寸、具体 CSS 类名；在数据中藏任意可执行脚本 |
| 剧情与持久状态 | 对语义动作做前置校验、推进阶段、写 Flag/笔记/物证、存档迁移与恢复；写入经现有 `StateManager` 的显式、幂等入口 | 读取 DOM 坐标、依赖动画结束时间、依据 CSS 可见性授予线索 |
| 交互控制与场景组件 | 把点击、键盘、触摸映射到同一个语义动作；根据当前状态生成可见镜头、热点、提示、返回与缺图替代内容 | 直接改 `localStorage`/Flag；把关卡分支、线索解锁顺序写死在 JSX 点击回调里 |
| 视觉样式与素材 | 以第三幕命名空间下的 CSS、局部组件和图片呈现第一人称视野、热点、对话、过场、响应式布局 | 决定剧情是否完成；将关键文字烘焙进图片；用视觉遮挡代替前置校验 |

分层是责任边界，不要求为每层新建目录或抽象框架。优先复用现有项目结构，按当前冻结工单的文件所有权落地。T00 建可复用的现场图像壳；T01–T07 扩展场景数据、局部交互和样式时，不能复制整套壳或另建一套状态系统。

## 易修改的具体约定

1. **统一动作语义。**“看向、靠近、返回、蹲下、检查、比对、收集、确认”等动作使用稳定 ID。鼠标热点、键盘列表和触摸按钮触发同一个动作处理入口；禁用动作提供可读原因，不靠隐藏按钮充当剧情校验。
2. **状态只存语义进度。**镜头可恢复位置、已确认线索和物证按工单进入存档；悬停、面板开合、动画帧、手电光斑位置等纯表现状态留在局部组件。重载后不重复授予 Flag，也不因样式变化丢进度。
3. **可换皮的场景壳。**热点位置、图片裁切和手电遮罩可作为独立呈现配置，但不能成为唯一线索入口。颜色、字号、按钮形态、面板布局、过渡时长、移动端断点集中在第三幕局部样式或变量中；不要把它们散落在剧情数据和状态方法里。确需动态坐标时只传必要的呈现值，不把剧情判断写进内联样式。
4. **图片可后补。**场景数据只引用稳定资源 ID；资源加载决定实际图片或本地占位。缺图时保留可见热点、文字替代和完整流程；替换为正式 JPG 不改 Flag、阶段或存档格式。关键标牌、代码词和可读文字由文字层渲染。
5. **转场可调整。**镜头淡入、音效、遮罩和提示节奏由视图层负责；下一镜头与阶段能否进入由数据和状态前置决定。关闭动画或启用 `prefers-reduced-motion` 时仍完整推进，不能依赖计时器完成剧情。
6. **改动边界可检查。**仅改变主题色、字体、热点外形、布局或过渡时长，应主要落在第三幕样式/表现组件；仅更换正式图片，应主要落在资源文件/映射；调整线索前置或 Flag，才涉及数据与状态。若一项纯视觉修改必须改 `StateManager` 或存档 schema，先检查是否分层失当。

## 验收与移交

- 每个 T 的执行 Agent 先按冻结工单完成剧情、缺图路径、键盘/鼠标/触摸、重载/回退/清零、离线运行和规定门禁，在独立分支提交。报告须附：实际分层文件表、稳定动作/资源 ID、状态写入入口、可调整的视觉参数位置、未完成项与运行截图或录屏。
- 阶段验收由 Codex 主审审查并决定是否合并。**T07 完成后的第三幕总验收与最终修改意见指定由 Codex `gpt-6-sol`、`high` 推理档执行**：从第二幕末连玩至启明遗址调查结束，复核剧情、存档、无图/有图、离线与多尺寸表现；将视觉和交互修改意见具体标到镜头/组件/样式，不让执行 Agent 自行宣告总验收通过。
- 总验收时至少做两项低成本可改性检查：临时调整一组第三幕样式变量，确认剧情测试及存档语义不变；将一个已登记图片切到本地占位，确认镜头和热点仍可用。检查后的临时改动不得混入最终提交。

## 可直接交给外部 Agent 的提示词

使用时将 `A3-TXX` 替换为当前**已冻结**阶段编号，并附该阶段的 `docs/work_orders/A3-TXX.md`。若规划稿与冻结工单不同，以冻结工单和主审后续书面修订为准。

```text
你是《暗潮》第三幕 A3-TXX 的外部执行 Agent。先读仓库 AGENTS.md、维护导航.md、docs/协作开发与Git工作流.md、已冻结的 docs/work_orders/A3-TXX.md、第三幕开发计划表、视觉与交互总规范，以及本公共开发契约。只在分配的独立分支和 worktree、工单允许的路径中开发；不得修改第一幕、第二幕或已验收的第三幕步骤，不得自行合并 main。

沿用当前 React + TypeScript + Vite 工程及 StateManager。将场景/资源数据、剧情状态、输入动作映射、React 画面组件、第三幕局部 CSS 明确分开。所有点击、键盘、触摸都调用同一个语义动作；Flag、物证和存档只由带前置校验的 StateManager 入口更新。组件不直接改存档，不在 JSX 中硬编码关卡推进；CSS、图片、动画不能决定剧情。T00 建可复用图像壳，后续 T 复用，不另建平行框架。没有正式图片时，使用本地可操作占位和文字替代，保持离线可玩。

开工时先确定本阶段的最小分层文件方案和稳定动作/资源 ID，然后直接按冻结工单实现；将方案随最终报告交付，不因常规实现选择停下等待确认。让主题、热点外形、布局、转场时长和图片能在不改 Flag/存档逻辑的情况下调整；让剧情前置变化能在不重写页面样式的情况下调整。保持第一人称连续视角、前后镜头方位和已有美术风格，完成键盘、鼠标、触摸及窄屏支持；尊重减少动态效果设置。

提交前运行工单列出的测试、构建、离线和 diff 检查，并在真实宽屏与手机尺寸浏览器中走通本阶段。交付分支名、基线与提交 SHA、全部变更路径、分层说明、实际验证结果、可替换视觉参数位置、缺图路径和遗留问题。你的交付等待 Codex 主审；T07 后的第三幕总验收与修改意见由 Codex gpt-6-sol high 完成，你不得自行标记总验收通过。
```
