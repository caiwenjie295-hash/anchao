# UX-234-REWORK 存档兼容说明

## 版本与存储

- localStorage 键保持 `anchao.save.v1`；当前结构版本为 schema 10。
- `hydrateState` 接受 schema 1–10，并将合法旧状态清洗为当前类型；未知 schema 或损坏根对象回退到默认结构。
- schema 1–6 没有第三幕字段，按默认第三幕状态补齐；第二幕、第一幕进度和桌面状态按原迁移规则保留。

## 新增及调整的可恢复字段

- 第二幕志异 `modules.act2Research.tales`：`supportingEvidenceIds` 保存原文证据片段，`selectedInferenceId` 保存玩家选定结论。未知证据 ID 和推论 ID 被移除；旧档缺字段时初始化为空，不伪造证据。
- 第二幕学校：保存选定来源、当前推论和双 S 明确比对动作。schema 1–9 已有的合法学校推进 Flag 不因新字段缺省被迫重做；schema 10 的双 S 结论需由有效双 S 观察、至少两个对应来源以及“有界时间变化”推论支撑。
- 第二幕 T07：仅保存已查看材料、实际播放片段、有效截图及已截取且已比较的帧。未定义材料、片段或帧 ID 会被清洗；比对帧必须先出现在截图集合中。播放 Flag 与实际覆盖片段校验，地点结论仍需有效外景对照。
- 第三幕：保存阶段、当前/已访问镜头、已检查线索和已确认结论。镜头/线索按阶段定义与可达路线清洗，不能仅靠写入更高阶段越级。
- 第四幕：新增/归一化 `broadcastPeriodsConfirmed`、`packageStep`、`broadcastIndex` 和 `finalMailOpened`，为分时段判断、三步藏笔记、六词广播与主动开信保存恢复点。

## 旧进度保护与语义迁移

- schema 1–9 的当前场景、既有 Flag、笔记、桌面应用状态与已有合法资料进度继续迁移；自由记事本正文及用户自定义笔记不由 UX-234 改写。
- schema 1–9 已完成的学校结论沿用旧有效 Flag，不要求为新来源字段重玩；迁入 schema 10 后，新完成的学校判断按新证据语义校验。
- schema 10 新的志异/学校/截图字段只追加语义进度，不替旧存档创建“玩家已读/已看/已比较”的假记录。
- schema 1–9 中若已解出旧谜题 `A4_P13`，迁移时将其映射为 `morning` 与 `night` 两个广播时段都已确认，因为旧谜题代表合并后的旧广播判断。
- 第四幕完成状态现在由剧情阶段、包裹三动作、六词广播索引、实际访问尾声节点及打开最后邮件共同校验；旧 `P21/P23` 解题标记保留为历史记录，但不再单独设为 T09/T10 继续门槛。语义条件不足的完成 Flag 会清洗，状态回退到最近合法节点而不清空其它幕进度。
- T09/T10 的继续条件仍然要求包裹与广播真实完成，以及玩家主动打开最后邮件；这几项状态可跨刷新恢复。

## 验证依据

`src/core/saveManager.test.ts`、`src/core/stateManager.test.ts`、`src/core/act4.test.ts` 与离线连续流程验证版本迁移、损坏 ID 清洗、旧进度保留、广播/尾声恢复和完成 Flag 语义。具体执行结果与范围见 `test-matrix.md` 和 `delivery.md`。
