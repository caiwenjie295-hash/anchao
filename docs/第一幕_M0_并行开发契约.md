# 《暗潮》第一幕 M0 并行开发契约

> 状态：权威执行契约  
> 基线：2026-09-17，项目尚无代码且不是 Git 仓库  
> 角色：Terra 编程助手（实现）、主任务（契约、审查、集成和文档）  
> 规则：Terra 可读但不得修改本契约

## 1. 目标

建立第一幕可长期扩展的 M0 技术底座：玩家能进入一个可操作的 Windows 11 风格私人电脑桌面，打开并管理六个应用窗口，桌面状态能在刷新后恢复。

### 必须交付

- React + TypeScript + Vite 工程。
- 桌面、任务栏、系统时间与六个应用入口。
- 微信、邮箱、浏览器、资源管理器、记事本、照片查看器的空壳窗口。
- 窗口拖动、调整尺寸、最小化、最大化、还原、关闭、层级聚焦、任务栏恢复。
- `stateManager`、`eventBus`、`saveManager`、`assetLoader` 的类型化基础实现。
- 根目录 `data/` 中的空数据集和可追溯元数据结构。
- 绘图资源完全缺席时的 CSS 占位表现。
- 至少覆盖状态和窗口核心逻辑的自动验证，以及可通过的生产构建。

### 非目标

- 不接入母亲消息、小A邮件或任何正式剧情。
- 不制作、生成或下载图片、图标、音频和字体。
- 不实现鸡头岭、山洞、破庙和照片曝光谜题。
- 不编写虚构邮件、聊天、搜索结果等正式内容。
- 不修改 `game/` 和项目根目录的小说稿件。

### 延后决策——不实现

- 正式背景图、应用图标和人物头像的风格与尺寸。
- 第一幕具体文案与时间轴。
- 三个线下场景的空间交互形式。
- 是否加入声音系统。
- 四幕全部游戏时长与第一幕单幕时长的最终数值。

## 2. 冻结共享规则

- 以 `game/01`–`game/04` 为第一幕开发基准；四幕整体流程只是方向参考。
- 流程冲突时，第一幕以 `03_暗潮_第一幕_流程推进开发文档.md` 为准。
- 所有正式数据与 UI 逻辑分离；React 组件不得内嵌正式剧情文本。
- 不引入 UI 组件库、动画库、图标库或全局状态库。
- 主视觉为 Windows 11 写实中性界面：冷白表面、深灰文字、少量系统蓝，不做通页玻璃卡片。
- 唯一视觉记忆点是“可聚焦的私人桌面”：仅任务栏和活动窗口使用轻微半透明与柔和阴影。
- 优先适配 `1366×768` 及更大桌面；小屏允许收缩为安全可用布局，不必模拟移动 Windows。
- 所有交互使用语义化按钮、可见键盘焦点和可读的 `aria-label`。
- 所有动效必须尊重 `prefers-reduced-motion`。
- 正式图片资源不存在时，使用标注资源 ID 的 CSS 占位块，不伪造最终图像。

## 3. 共享接口

### 3.1 应用 ID

```text
wechat | mail | browser | explorer | notepad | photos
```

对应可追溯 UI ID：

```text
UI_A1_A_001 微信
UI_A1_A_002 邮箱
UI_A1_A_003 浏览器
UI_A1_A_004 资源管理器
UI_A1_A_005 记事本
UI_A1_A_006 照片
```

### 3.2 持久化状态

- localStorage 键名：`anchao.save.v1`
- `schemaVersion`: `1`
- 顶层字段：`game`、`desktop`、`settings`
- `game`: `act`、`phase`、`flags`、`discoveredClueIds`
- `desktop`: `windows`、`activeAppId`、`openedOnceAppIds`
- 每个窗口：`appId`、`status`、`bounds`、`restoreBounds`、`zIndex`
- `status`: `closed | normal | minimized | maximized`
- `bounds`: `{ x, y, width, height }`，单位统一为 CSS px。
- 未知字段读取时忽略；结构损坏时回退默认状态，不让页面白屏。

### 3.3 事件总线

M0 固定公开事件：

```text
app:opened       { appId }
app:closed       { appId }
window:focused   { appId }
flag:changed     { flagId, value }
save:completed   { schemaVersion: 1 }
```

未使用的剧情事件不提前创造。

### 3.4 数据文件

`data/contacts.json`、`chats.json`、`mails.json`、`browser_pages.json`、`files.json`、`images.json`、`clues.json`、`flags.json`、`events.json` 统一采用：

```json
{
  "schemaVersion": 1,
  "items": []
}
```

M0 不在其中填入正式剧情。应用入口元数据可单独使用 `data/apps.json`，每项必须包含 `id`、`appId`、`title`、`act`、`phase`、`source`、`purpose`、`unlockCondition`、`relatedFlags`、`notes`。

### 3.5 占位资源

- 桌面背景占位 ID：`IMG_A1_A_001`
- 应用图标占位 ID：`IMG_A1_A_002`–`IMG_A1_A_007`
- 占位容器必须有 `data-asset-id`；不得创建伪最终图片文件。

## 5. 角色工作包

### Terra 编程助手

**目标：** 在独占写入区内完成 M0 技术底座。

**必须验证：**

```text
npm test
npm run build
```

**禁止：**

- 修改契约、导航、进度、剧情基准和小说文件。
- 把剧情文本写入 React 组件。
- 为了展示而引入正式美术或第三方资源。
- 越出 M0 接入母亲消息或其他剧情。

**最终报告必须包含：**

```text
Role: Terra 编程助手
Delivered: 实现行为与产物
Changed paths: 所有修改路径
Validation run: 命令及结果
Deferred or blocked: 延后项或 none
Cross-boundary requests: 跨边界请求或 none
```

### 主任务（集成者）

**目标：** 审查 Terra 的全部交付，修改仅属于文档区的记录，执行最终组合验证。

**交付：**

1. 检查目录、ID、状态、事件与数据是否符合 01–04。
2. 检查窗口交互、持久化容错、键盘可用性和 reduced motion。
3. 运行测试、构建和必要的本地视觉验收。
4. 更新 `progress_log.md`、`todo.md`、`changelog.md` 与 `维护导航.md`。

## 6. 执行和集成顺序

1. 主任务写入本契约与初始导航。
2. Terra 在独占代码区实现工程、数据空壳和测试。
3. 主任务在 Terra 运行期间只阅读和准备审查，不写入 Terra 区域。
4. Terra 完成后，主任务审查实际文件及验证结果。
5. 如发现代码缺陷，由 Terra 继续修改其独占区；主任务不直接绕过边界打补丁。
6. 验收通过后，主任务统一更新文档。

## 7. 冲突协议

- 命名冲突：本契约优先，不在局部重命名。
- 需要跨区修改：停止该写入，向主任务报告。
- 现有文件：全部视为用户工作，不还原、不覆盖。
- 环境限制：保留最小可行回退方案，精确报告限制。
- 契约缺陷：只能由主任务修改。
